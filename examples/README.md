# 大表示例与填写要求

`catalog.md` / `field.md` 已经按大表组织。这里放两张写法示例，方便对照列怎么填；单篇详细核对仍写在 `notes/<id>.md`。

| 文件 | 内容 |
|---|---|
| [`llm-testing-table.md`](llm-testing-table.md) | 表一：大模型用于 GUI 测试（2024–2026），对照 `catalog.md` 的列写法 |
| [`field-table.md`](field-table.md) | 表二：理解测试领域的经典与非大模型工作，对照 `field.md` / 领域概念怎么挂论文 |

## 填写要求

**收什么**
- 表一对应具体方向论文：优先收 2024–2026 年的原始论文；综述放 `field.md`，不要和具体方法挤在同一张总表。
- 表二对应领域背景：收帮助理解领域的经典 / 非大模型工作，并标出对应概念或综述位置。

**每列怎么写**

| 列 | 要求 |
|---|---|
| 论文 | 简称加中文题目，并链到 `notes/` |
| 年份 · 场合 | 必须在会议页、出版社页或 DBLP 上核实；没核实写“未核实”；预印本写“arXiv 预印本（未见录用）” |
| 第一作者单位 | 只写第一作者 |
| 三问 | 测什么 / 怎么知道错了 / 测得够不够，可加 README 里的 `execute`、`maintain`、`eval` |
| 动机 | 翻译成中文，**尽量保留原文的意思和信息**，不要压缩成一句话；有关键数字（如“43.2% 截图有显示问题”）要写上 |
| 贡献 | 按论文自己列的条目逐条翻译，用 ①②③ 编号 |
| 方法 | 写成 3–5 步，让没读过论文的人能看懂流程；说清楚输入是什么、判定从哪来 |
| 实验与关键数字 | 数据规模、对比基线、主结果数字、真实 bug 发现与确认数；论文前后数字不一致时并列写出并注明 |
| 作者承认的不足 | 论文自己写的局限，翻译过来 |
| 还没解决的问题 | 我们读完认为它没做到的地方，**用白话写**，例如“只看文字不看截图，图标按钮会漏掉” |
| 和我们的关系 | 同一格分成两点：①“与 UX testing 的关系”，结合 UX-Agent 的截图候选、布局树复核和主动滑动验证说明异同；②“与 GUI testing 的关系”，说明论文补上探索、执行、oracle、维护或评测的哪一环 |
| 论文叙事（问题→方法→证据） | 先用完整句子交代研究问题和旧方法不足，再说明核心方法及支持结论的实验；不使用依赖其他单元格才能理解的开头 |

**原则**
- 数字只写原文里出现的，不自己算、不补。
- 没读到全文的格子写“未核实”，不要猜。
- 表格末尾可写三到五条“从这张表能读出什么”，方便横向比较。
