# 大表示例

平时最常看的应该是一张大表：每篇论文一行，一眼能看出研究脉络、各家用了什么方法、还差什么。单篇笔记可以有，但只是补充。

| 文件 | 内容 |
|---|---|
| [`llm-testing-table.md`](llm-testing-table.md) | 表一：大模型用于 GUI 测试（2024–2026），对应 `catalog.md` |
| [`field-table.md`](field-table.md) | 表二：理解测试领域的经典与非大模型工作，对应 `field.md` |

## 填写要求

**收什么**
- 表一只收 2024–2026 年的原始论文；综述最多留一两篇当入口。
- 表二收帮助理解领域的经典工作，每篇标出对应 `field.md` 的哪个概念。

**每列怎么写**

| 列 | 要求 |
|---|---|
| 论文 | 简称加中文题目 |
| 年份 · 场合 | 必须在会议页、出版社页或 DBLP 上核实；没核实写"未核实"；预印本写"arXiv 预印本（未见录用）" |
| 第一作者单位 | 只写第一作者 |
| 三问 | 测什么 / 怎么知道错了 / 测得够不够，可加 README 里的 `execute`、`maintain`、`eval` |
| 动机 | 翻译成中文，**尽量保留原文的意思和信息**，不要压缩成一句话；有关键数字（如"43.2% 截图有显示问题"）要写上 |
| 贡献 | 按论文自己列的条目逐条翻译，用 ①②③ 编号 |
| 方法 | 写成 3–5 步，让没读过论文的人能看懂流程；说清楚输入是什么、判定从哪来 |
| 实验与关键数字 | 数据规模、对比基线、主结果数字、真实 bug 发现与确认数；论文前后数字不一致时并列写出并注明 |
| 作者承认的不足 | 论文自己写的局限，翻译过来 |
| 还没解决的问题 | 我们读完认为它没做到的地方，**用白话写**，例如"只看文字不看截图，图标按钮会漏掉" |
| 和我们的关系 | 对我们的课题意味着什么：可以引用来说明什么、和我们的方法有什么异同 |
| 一段话 | 它是怎么讲故事的：从什么问题出发，用什么办法，用什么结果收尾 |

**原则**
- 数字只写原文里出现的，不自己算、不补。
- 没读到全文的格子写"未核实"，不要猜。
- 表格末尾写三到五条"从这张表能读出什么"，这是最有用的部分。
