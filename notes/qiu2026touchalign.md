# TouchAlign：主动点按探测，判断控件看起来可点击的区域是否真的可点击

## 一页读懂

| 问题 | 论文的回答 |
|---|---|
| 测什么 | 按钮、图标等控件的可见区域与真实点击生效区域是否明显不一致：可见边缘点不中、不可见空白触发操作，或点击区域整体偏移。 |
| 为什么需要实际操作 | 控件树声明的矩形未必是运行时真正接收触摸的范围；截图也看不到隐藏的触摸边界。 |
| 输入与输出 | 输入为截图和可重放到该页面的动作序列；输出为可见框、实测点击框、两框重合分数和页面报告。不是从应用首页自动寻找所有风险页面。 |
| 核心方法 | OmniParser V2提取可见框；以中心点击的结果为参照，向四个方向二分探测；静态结果用SSIM比较，动态结果用多模态模型判断功能效果是否等价。 |
| 主要证据 | 美团65页1,745控件，实测框对人工真值IoU .896；175个人工注入错位，P .820/R .857。另在227页报告104项，86确认、85修复。 |
| 关键边界 | 中心点应能正确触发目标功能、页面应可恢复；四方向搜索假设触摸区域较规则。不检测文字截断，也不验证中心点击所触发的业务功能本身正确。 |

## 一段话介绍

移动应用中的按钮可能显示为完整矩形，但只有中间一部分可点击；也可能为了扩大触摸范围而让旁边空白甚至邻近按钮触发同一操作。TouchAlign研究这种可见区域与实际交互区域的错位，而不是仅检查控件是否足够大。它先从截图识别可见框，再实际点击控件中心建立效果参照，向上下左右反复探测哪些位置仍触发相同功能，得到交互边界。静态画面用图像相似度比较，推荐流等动态画面则用多模态模型比较操作效果，最后根据两种边界的重合程度筛查缺陷。在美团的人工注入实验中，精确率为82.0%、召回率为85.7%；工业应用另外确认86项问题、修复85项。这是直接把主动交互作为UX判错证据的正式工业论文，但它依赖可重放页面、正确的中心点击参照和较规则的触摸区域，不能推广为一般功能正确性或全应用探索方法。

## 关键术语与阅读前提

- **视觉边界与交互边界**：前者是截图中用户看见的按钮或图标范围；后者是实际点击后触发该控件动作的范围。两者可能因父容器接收事件、额外触摸代理或覆盖层而分离。见[触摸边界与主动探测](../glossary.md#visual-interactive-misalignment)。
- **VIM**：visual-interactive misalignment，本文定义的视觉与交互边界错位，包括缩小、膨胀、偏移。它与截图上两个图形重叠不是同一个问题。
- **IoU（交并比）**：两个区域交集面积除以并集面积。本文两处使用不同对象：一处比较工具实测点击框与人工真值，评价测量准确性；另一处比较可见框与实测点击框，决定是否错位。两种分数不可混用。
- **SSIM**：图像结构相似度，用于快速比较点击后的两个画面；动态推荐内容可能使相同功能的结果图也不相似。
- **oracle（判错依据）**：本文先有一个判断“此处点按是否与中心点功能相同”的交互oracle，再用边界差异判断UX异常。模型并非直接看单张截图报告所有UX问题。
- **二分搜索**：不断把搜索区间缩半，缩小边界位置范围；这种方法依赖沿搜索方向的点击效果变化具有可用于定位边界的规律。

## 动机

依据§1–2，PDF第2–4页。为满足最小触摸目标和控件间距要求，开发者会扩大某个图标的触摸区域、缩小相邻区域，或把事件绑定到不可见父容器。后续布局变化可能使这些调整与可见图形不再一致。

原文图1给出三类后果：购物车按钮边缘点按无效；地址栏扩大后的交互范围截获返回按钮的触摸；删除按钮的点击范围偏移，使点击保存附近意外触发删除。图4还有导航栏中分享与收藏、更多与搜索相互干扰的案例。关键不在于中心点击能否完成任务，而在于用户根据可见形状作出的空间预期是否可靠。

动机研究选择16个热门应用、134个核心页面和2,361个交互元素，两名作者独立密集点按后识别53项错位，标注一致性κ=.87。研究只纳入视觉指示清晰的独立按钮、图标，排除复合控件；这些数据支持样本中问题存在，不能直接估计整个移动应用生态的缺陷发生率。

## 方法与核心技术

整体链路是：**恢复指定页面 → 识别控件可见框 → 中心点击建立参照 → 选择比较方式 → 方向性点按探测 → 两框对比 → 生成待确认报告**。依据§3，PDF第4–6页。

### 1. 输入是可复现的页面状态

每个状态含截图，以及在真实被测应用上重放到此状态所需的动作序列。OmniParser V2从截图预测可交互元素及其矩形框；该框既定义探测对象，也成为后续视觉边界参照。

这一步没有读取控件树或业务源码。UIAutomator2用于截图，ADB执行触摸；“用到自动化接口”与“依赖接口里的树结构判断边界”需要区分。

**范围**：工具不是目标驱动页面导航器。评测用STOAT从业务入口探索30分钟收集页面，再经作者人工去重筛选；工业流程由QA选择页面。因此全文没有证明它能够自主优先发现最可能出现此类UX问题的页面。

### 2. 中心点击定义该控件的参考效果

先保存操作前画面，再点击可见框几何中心，保存操作后画面。工具把这个前后变化当作目标控件的功能参照。例如点击分享后出现分享面板，后续其他位置是否也能打开同类面板，就能用于推断这些位置是否属于分享的有效点击区。

作者明确假设经过常规质量保障的生产应用能正确响应中心点。**这一假设不等于已经验证业务语义正确**：若中心本身点不中、被覆盖，或错触其他控件，参照可能失效。工具比较的是与参照效果一致，而非与独立需求规格一致。

### 3. 静态与动态结果采用不同的交互oracle

预处理阶段对中心执行两次点击，比较两次结果图的SSIM。相似度高于设定阈值时，视为较静态的结果页面，之后直接以SSIM判断探测结果是否与参照一致。实验阈值θ=.8。

如果推荐商品、广告、轮播等导致两次结果明显不同，则使用语义oracle。模型收到三张图：操作前、中心点击后、探测点击后。先从前两张推断控件功能，再判断第三张是否产生相同功能效果，并要求忽略推荐流等动态装饰内容，输出是否匹配和理由。

正文以GPT-4o举例说明多模态模型能力，**实际评测配置是Qwen3-VL-Flash**，不能把例举模型写成实验后端。也不能把忽略动态内容理解成已经区分所有业务重要变化与无关变化。

### 4. 沿四个方向探测交互范围

从中心向上、下、左、右分别搜索，初始区间延伸到对应屏幕边缘。每次点击当前区间中点：若结果与中心参照功能一致，就向外扩展；否则向内收缩。反复缩小范围，得到各方向边界点，形成推断的点击区域。

每次探测涉及恢复指定页面状态、点击与观察。输入的重放序列是必要条件，但正文未完整说明所有返回、不可逆操作、网络状态与数据恢复策略，也未给出不同页面下重放失败的统计。

**我们的观察**：四向搜索不是对全部二维像素的穷尽探测。它对环形、非凸、多块分离或相邻同功能区域的处理缺少独立实验；如果同一方向先命中、再离开、又命中同功能区域，简单二分的单一边界前提可能不成立。伪代码也未展开像素步长和终止容差的工程细节，不应自行补成已验证实现特征。

### 5. 边界差异产生缺陷候选，而非所有差异直接报错

最后计算可见框与实测交互框的IoU，低于τ=.65时报告，并按IoU从低到高排列。阈值来自美团过去三个月以上相关用户投诉的分析：作者称90%以上用户报告的交互失败对应IoU低于.65；历史样本数量和独立验证划分未充分给出。

输出在截图上叠加实测框，帮助开发者确认。扩大触摸区域本来可能是合理无障碍设计，因此作者也记录了需与设计团队讨论、尚未确认的报告。固定重合阈值是该工业环境中的筛查准则，不能直接当成所有设计系统的统一正确性定义。

### 6. 完整案例：为什么中心能点中仍可能是问题

依据原文图4：更多图标的交互区域向旁边扩张，覆盖了搜索图标附近。只在两者中心点击的常规用例可能均能通过；TouchAlign在更多图标外侧做探测时，仍观察到更多菜单的相同功能结果，因此推断它的有效点击区域比可见框更大。两框IoU过低触发报告，开发者据框叠加图检查与搜索目标的干扰。

这个例子展示的是**通过有目的的局部操作获得隐藏交互状态的证据**。它不是“让模型自由探索更久”，也不是“截图看起来不整齐就报错”。

## 实验

### 数据、真值与环境

| 实验 | 设置与分母 |
|---|---|
| RQ1边界测量 | 美团五业务线65页、1,745交互元素；4名作者分别标注，计6,980份框标注；平均标注间IoU=.932，最终真值取4份区域的交集。 |
| RQ2缺陷检测 | 在上述数据中向175个元素注入缩小、膨胀、偏移错位；其余1,570项为负样本。注入由历史投诉启发，修改显示位置/尺寸或事件绑定区域。 |
| RQ3工业部署 | 2025年5–12月，由QA选取日访问量超过10万的高影响页面；227页、4,978元素，统计报告、确认、修复。不同于RQ1/RQ2数据规模。 |
| 运行环境 | MacBook Pro，六核2.6GHz i7；美团V12.50.203；小米12、三星Galaxy A53，两设备统一1080×2400；SSIM阈值.8、错位阈值.65。 |
| 重复与资源 | 未明确报告随机种子、独立重复次数及误差区间。价格按实验时模型官方计费计算，不是当前价格。 |

出处§4.1，第6–7页。最终真值取交集使标注较保守，但人工标注也依赖触摸探测；没有独立系统级事件路由真值可供核对。两台设备使用同分辨率，不构成跨尺寸和跨平台系统实验。

### RQ1：是否正确测到真实点击边界

表3（第7页）比较的是**工具预测的交互边界与人工真值**，不是最终缺陷检测精确率。

| 方案 | 平均IoU | 每元素探测时延 | 每元素模型费用 |
|---|---:|---:|---:|
| Accessibility Scanner | .706 | .162秒 | $0 |
| 只用图像相似度 | .633 | 51.521秒 | $0 |
| 全部使用模型语义比较 | .914 | 319.417秒 | $.018 |
| 混合策略TouchAlign | .896 | 132.247秒 | $.005 |

时延明确**不包含页面加载时间**，不能写成每个元素完整端到端只需132秒。混合策略相对全语义方案降低调用开销，但框测量平均IoU也从.914降至.896；不能称在所有指标上都最好。Accessibility Scanner给出的结构区域与实测区域不同，尤其在混合网页/原生页面中不稳定；它是特定比较条件下的基线，不意味着所有结构分析方法永远无用。

### RQ2：是否找到人工注入的错位

表4（第7页）：150真阳性、33假阳性、1,537真阴性、25假阴性，总计1,745元素。

- 精确率：150/(150+33)=.820，回答报告的候选中多少真错位。
- 召回率：150/175=.857，回答175个注入错位中找到多少。
- F1=.838；假阳性率33/1,570=.021。

**2.1%假阳性率不等于报告中仅2.1%是误报**：报告里误报为33/183，约18%。实验以注入问题为主，不应将该召回率写成所有真实工业缺陷的召回率。Video子集精确率.647、召回率.733，也表明跨业务线效果有差异。

### RQ3：工业报告是否被开发者接受

表5（第8页）中，227页报告104项，86项由开发者确认、85项已修复；确认比例82.7%。确认问题中，膨胀67项、缩小17项、偏移2项。

未确认的18项不应全部直接记作已证误报，其中部分仍需与设计团队讨论。工业测试没有给所有未报告元素建立完备缺陷真值，因此**不能算工业召回率**。

作者另称QA每天可审查约160个工具报告元素，而全人工探索每天检查约72个元素。两组对象分别为高风险报告与所有被检查对象，不是对照充分、相同任务下的时间实验，不把它转换成确定的整体劳动效率提升倍数。

## 局限

### 论文承认的

§5.3，第9–10页：视觉解析器和模型判断能力会影响检测准确性；主要评测来自美团与统一分辨率Android环境，异构分辨率与iOS仍留待研究。工业未确认问题也体现判定与具体设计规范之间的边界。

### 我们的观察

1. **参考操作可能失效**：中心点击被假定为正确，不能发现或排除它自身已经错触、被挡或未产生可观察结果的情况。
2. **局部搜索结构假设**：四向边界推断未系统验证不规则、非连通触摸区域或同效果不同控件，不能当作完整事件路由还原。
3. **恢复代价与副作用**：反复点击可能提交订单、切换持久状态或消耗一次性数据；全文未给出覆盖这些动作的通用回滚机制和排除清单。
4. **视觉框不是设计规格**：解析模型的框可能过松/过紧；固定IoU也无法独立决定刻意扩大触摸目标是否合理。
5. **探索入口已给定**：STOAT采集加人工筛页、QA选页，未研究UX风险如何引导全局探索和页面优先级。
6. **可复现性边界**：没有看到公开代码、内部数据下载与完整重复协议；可获取论文全文不等于实验资产公开。

这些是由方法与实验边界提出的后续核查问题，不是已经证实无人解决的研究空白。

## 和我们课题的关系

### 与 UX testing 的关系

直接研究可见交互目标与真实触摸反馈的一致性，补充UI-Lens的静态视觉缺陷视角。它表明部分UX问题必须主动操作才能判断，操作的价值是暴露截图中不可见的交互边界。与滚动复核截断候选共享“候选→局部动作→补充观测→判断”的结构，但动作目的不同：这里重建触摸生效区域，不是滚动恢复被截断内容，也不检测全部重叠、遮挡或文字溢出。

### 与 GUI testing 的关系

属于局部执行加关系oracle：以中心效果作为行为参照，主动探测空间边界，再将测量转为UX缺陷候选。可作为研究“测试动作由缺陷假设驱动”的具体例子；其页面入口、可恢复性和业务参照均有前提，不能替代通用目标导航、完整功能验证或探索充分性评价。
