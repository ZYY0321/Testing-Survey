# UI-Lens：通用多模态模型能否分清真实界面显示缺陷与正常设计

## 一页读懂

| 问题 | 本文的回答与边界 |
|---|---|
| 研究什么 | 在商业移动应用截图和连续页面中，评测模型发现溢出、裁剪、重叠、缺失、异常省略及文本不一致的能力。属于GUI显示质量测试的评测，不是自主探索代理。 |
| 为何需要它 | 识别文字/按钮不等于辨认文字是否越界；卡片空白、可滚动列表露出半个元素等正常设计，也可能被误报。 |
| 新增产物 | 专家定义和标注的显示缺陷benchmark；中文4,759张图、5,356个标注实例，另报告英文3,392张图；9种通用模型的统一评价与错误分析。 |
| 输入与输出 | 单屏：截图加某一缺陷的规则，输出结构化判断和描述。序列：逐屏描述→跨屏分析→分类整理，输出问题、涉及页和细节。没有让模型操作应用。 |

## 一段话介绍

UI-Lens提出的问题是：模型能读懂一张页面，是否就能准确判断它有显示问题？作者以商业手机、平板及折叠屏应用构建截图数据，先由设计专家明确“什么算异常、哪些正常设计不应报告”，再分别评价五类单屏缺陷和一类跨屏文本不一致。论文显示，细小越界和裁剪、正常交互区域的边缘露出、需要比较多个页面的语义差异，容易引发漏报与误报。它提供的是显示缺陷评价任务、标注规则和模型能力证据，而不是一种自动修复界面、探索新页面或验证全部业务功能的方法。本文为CVPR 2026主会论文，以下同时依据11页主文和另行发布的14页补充材料。

## 关键术语与阅读前提

- **[显示缺陷与正常设计边界](../glossary.md#uilens-display-taxonomy)**：本篇不是评价“好不好看”，而是按明确规则判断元素可见性、边界、信息完整性及跨页面呈现一致性。但某些规则包含设计规范或呈现一致性，不都等于业务逻辑错误。
- **[Bounding box（框）](../glossary.md#widget)**：标记问题位置的矩形。数据有位置框，不代表本文主指标评价了框是否精确；单屏任务主要看整张截图的某类异常是否存在。
- **[Precision / Recall / F1](../glossary.md#metrics)**：报告异常中正确的比例、实际异常中找到的比例及二者调和平均。正常和异常各半时，全判正常也有50%准确率，但异常召回为零；不能据此说该模型已经能找到一半缺陷。
- **Zero-shot CoT（零样本分步推理提示）**：不给完整演示样例，但提供规则、观察步骤和输出格式，要求模型按这些步骤检查。不是完全不给缺陷定义。
- **[模型作为评判器](../glossary.md#uilens-evaluation)**：开放式问题描述难以用字符串相等判断，因此用judge判断预测问题与人工标准答案是否语义对应。模型本身也可能误判，需与真值来源区分。
- **标注一致性系数**：论文用Krippendorff’s alpha衡量多个专家标注的一致程度，不是缺陷检测准确率，也不是所有标注都一定正确的证明。

## 动机：看懂页面与发现页面有错，是不同能力

引言指出，OCR和一般界面理解常在正常页面上测试；但显示检测需要区分“文本存在”和“文本笔画只露出一部分”，也需要判断正常遮挡、滚动容器的边缘截断是不是错误（主文§1，第1页）。从旧数据集抽出的简单界面未必代表当前商业应用的大字模式、深色模式、复杂卡片及跨页购买流程。

图1把三类任务区分开：OCR读文字，UI理解识别组件，显示质量检测判断呈现是否异常。主文图7提供具体失败：模型把优惠券卡片中正常留白当成缺失信息；把环形图中的问号占位当数据丢失；将横向可滚动容器的边缘露出当裁剪错误。这些不是单靠把OCR识别率提高就能解决的相同任务（主文§4.1，第7–8页）。

## 贡献

作者在主文第3页列出：①构建来自11个商业应用、21类采集设备的专家标注数据；②定义六种显示检测任务；③评价9种模型并分析边界感知和跨屏语义推理失败。本文归类为benchmark、empirical。没有训练新检测模型，也未提供自主交互探索或自动修复算法；使用复杂提示并不意味着贡献了多Agent测试框架。

## 方法与核心技术：数据规则、模型处理与评价怎样接起来

### 1. 先采真实截图，再补稀缺的异常样本

专家从11个中文商业应用手动采页面，涉及短视频、内容创作、购物、团购和阅读等场景；设备覆盖手机、平板、折叠屏，操作系统包括iOS、iPadOS、Android、HarmonyOS，适用时包含明暗、大字与标准模式以及平板横竖屏（主文§2.1；补充A，第1–2页）。界面采集保留设备、应用、页面ID和模式等元数据，序列则按实际购物、团购等操作流程获取。

真实异常稀缺，因此8位UI/UX专家额外合成1,030张中文异常正例。补充A.6给出完整原文案例：先取正常搜索框截图，在Figma用与背景同色矩形遮掉一部分文字，再加上字体、字号、颜色一致的省略号，制造异常省略。它是一张经过人工图像编辑的缺陷样本，**不是通过修改应用代码实际触发的程序缺陷**，不能计入真实bug发现数。

作者用35,308次预测比较合成与真实样本，报告平均准确率62.82%/61.81%、按类别的Pearson相关r=0.88（主文第3页）。这支持两组在这些被测模型上的难度有相近表现，不证明其根因、交互可复现性或所有视觉分布完全等同。

### 2. 六种任务必须知道各自在判什么

以下根据补充B及C的具体规则整理；它们是本benchmark的标签定义，不应直接提升成所有应用的统一设计标准。

#### Text Overflow：文字溢出可见边界

文字像素越过明显容器边界；文字和图标作为一个整体越出共同容器；或含文字的容器越出父容器，都属于范围。关键前提是用户能从边框、背景、阴影或形状看出容器边界。若背景透明且根本没有可见边界，不能只凭猜测认为文字越界。提示还排除视频水印、视频内文字和屏幕录制浮标遮挡等情况（补充B.1/C.1，第2–3、5–6页）。

原文图4用红框展示内容伸出其承载区域。检测器需要同时观察文字、边界及相对位置，不只是读出那段文字。

#### Cropped Content：内容被裁切而呈现不完整

另一组件、屏幕边缘或容器导致内容显示不全，以及文字突然被硬切断，均在标签示例中。但可滚动元素在视口边缘自然裁切、渐隐效果、用户生成内容及不明显的裁剪排除（补充B.2，第2–4页）。例如横向列表只露出下一张卡片的一部分，是提醒还能横滑的正常设计，不宜直接报错。

**规则边界疑点：**补充C.2又把靠近屏幕边缘造成的裁剪列作例外，B的表4却将屏幕边缘列作裁切来源之一。这说明标注定义与提示细则未完全一致，需要对具体案例核验，不能把任何露出半个字符都判成相同缺陷。

#### Container Overlap：控件或容器错误重叠

过长文本覆盖其他内容，或整体组件位置错误遮住其他组件，属于范围；弹幕、视频内容、录屏组件、渐变效果中的重叠排除（补充B.3，第3–4页）。提示C.3还排除toast与弹窗引起的重叠，即并非所有浮层覆盖都应报错（第8页）。

这与UX测试的遮挡问题直接交叉，但“浮层暂时挡住背景”可能是正常交互。数据集规则的目的，是让模型根据预期设计区分异常与正常层级关系，不是统计所有矩形相交。

#### Undisplayed Content：应该存在的信息没有显示

独立功能区内部空白、重复列表中某个已加载单元异常空白、明显不对称留白或有标题却无下方内容等是候选。默认头像、占位图、加载状态、创作页待上传内容为空，以及页面空间不足造成未显示，按规则不报告（补充B.4/C.4，第4–5、8–9页）。提示把部分不对称内间距写为大于8像素，但标注表只给定性描述，不能当作所有应用通用阈值。

主文图7的“优惠券右侧留白”和“环形图问号”说明，仅靠“这里空着”推断缺失会产生幻觉。真值仍依赖专家对组件语义及规则的判断。

#### Abnormal Text Ellipsis：不恰当的省略号

按钮/标签本应表达完整意图却被省略；文字短到中文≤2字符、英文≤4字符或数字≤4位仍出现省略；系统提示在动词处省略导致意思不全；或者文字/图标后还有大块空间却提前省略，属于规则范围。长文本在有限空间的正常省略和“更多”等有明确设计意图的省略不报告（补充B.5、表7、C.5，第4、6、9页）。

这比“看到省略号就是bug”更细；也不同于没有省略号的硬裁剪。前述Figma合成案例就是该任务的一种异常，并不代表所有短文本省略都经过交互证明为故障。

#### Text Inconsistency：跨页面信息呈现不一致

按真实流程依序获取截图，找数值或措辞冲突、关键优惠信息在跳转后丢失、结算时突然出现此前未披露的重要信息。补充表8的例子包括58.9与51.6、列表中的优惠在详情页消失，以及到支付阶段才披露额外服务（第7页）。这种任务需要连接同一商品或流程中多张页面，无法仅用一张截图判断。

**标签范围比事实矛盾更宽：**同一表也将500g与0.5kg的单位写法差异、工作日有效与周末不可用的等义措辞列作规范冲突/表达不一致。这些并非数量或逻辑上必然矛盾，而是呈现一致性标准。因此本任务11.44% F1不能直接解释为“模型发现真实业务逻辑bug的F1”。

### 3. 专家怎样建立真值

8位专家平均7.8年经验，先制定规则，再标问题框；另一位专家复核，分歧由专家组讨论裁决。在1,000个多人标注实例子集上，alpha=0.8417（主文§2.2，第4页）。序列任务另建包含相关页面、违反的规则和问题细节的答案集。

单屏真值为是否存在该种显示异常，带框的实例用于位置标注；序列真值为问题列表。专家一致性表明规则有可重复性，但不等于已获取开发者认可，更不表明每个合成异常能在真实应用运行中复现。

### 4. 被测模型具体输入和输出

单屏检测每次给截图与某类缺陷的专用提示，提示包括角色、应报告/排除条件、观察与复核步骤。输出JSON包含总问题数、问题描述和上中下/左中右的粗略位置（补充C.1–C.5）。评价主要把总数转成截图的有无异常类别。没有从图像自动点击页面，也没有获取控件树或源码。

序列不是一次把“全部截图+有没有问题”简单交给模型。补充C.6（第10页）依次给三类提示：①逐屏描述可见布局、文字与重要业务信息；②结合这些信息分析跨页一致性，返回涉及页号与细节；③将初步问题归为数字、措辞、信息丢失或额外信息并整理。第二步要求不猜隐藏信息，第三步要求保持页号和描述内容。这是信息提取—分析—整理的提示流程，不能据角色名就认定是多Agent探索系统。

给定截图处理完成后停止，产物是问题描述列表。导航、输入、滑动、失败恢复均不是模型在实验中执行的任务。

### 5. 评价怎样判断预测正确

单屏以“该截图是否存在指定类别”计算TP/TN/FP/FN，指标分母是截图，不是标出的每个异常实例。序列评价则依次检查：预测涉及页面与标准问题页面有非空交集，且描述语义一致，即认为匹配（主文图5；补充E，第11–12页）。不要求相关页集合完全一致，也没有要求模型逐像素定位。

序列报告不匹配为FP，标准问题没被匹配为FN；因为开放式描述没有明确的全部正常陈述集合，不算accuracy。主文称引入judge模型，但主文和附录没有明确提供judge的身份、校准人工核验和完整匹配实现。补充公式把matched predictions直接用于recall分子，若多个预测重复匹配同一真值，需一对一配对/去重才有清楚含义；原文没有展开冲突处理。这是本笔记的复现风险判断，并非已证实实验真的重复计数。

### 模型与运行协议

7个闭源：Seed1.5-VL、Seed1.6、Seed1.6-Vision、GPT-4o、GPT-4.1、GPT-5、Gemini-2.5-Pro；2个开放模型：GLM-4.5V、Qwen3-VL-235B-A22B。统一零样本CoT，每配置运行两次取平均（主文§3.1；补充D）。全部通过各平台MaaS API，temperature=0.1、最大输出8,192 token、top-p为0.1或0.2；每模型并发20，表列QPM120/TPM600,000，用LangSmith管理实验（补充第10–11页）。这些是作者报告的配置，不是我们复现成功的参数。

附录只给年月级版本标识与文档地址，未给所有不可变模型快照及完整API调用日志。未报告方差/置信区间或显著性检验；两个运行的平均值不足以表明小幅排名差必然稳定。没有测试训练后新检测器，亦未报告探索时间预算和新缺陷修复数。

### 单屏分类的主要结果

表2（主文第7页）按模型对各任务评分，再在ALL行报告任务均值：

| 任务 | 各模型平均accuracy | 各模型平均F1 |
|---|---:|---:|
| 文字溢出 | 50.04% | 22.19% |
| 内容裁剪 | 54.07% | 42.05% |
| 容器重叠 | 54.14% | 33.75% |
| 内容未显示 | 67.00% | 57.78% |
| 异常省略号 | 74.89% | 75.24% |
| 跨屏文本不一致 | 不适用 | 11.44% |

“接近随机”主要针对均衡单屏任务的accuracy；不能把F1也用同一50%阈值机械解释。比如GPT-5溢出accuracy50.67%、F1仅6.80%，说明正确分类正常样本并不等于有效找到异常。Gemini的溢出accuracy52.32%但F1 64.67%，结合其整体高召回、较低精确率看，它更倾向报告候选；二者不同的风险偏好不能只用accuracy排序。

表2逐类F1值得保留的对比：Gemini在溢出/裁剪/重叠/缺失/省略为64.67/61.60/65.05/67.68/74.97%；Seed1.6-Vision为52.54/62.31/63.23/69.26/77.30%。GPT-5前三类为6.80/25.51/34.65%，后两类60.18/81.13%。GLM重叠F1为N/A，原文未清楚说明该缺失值在总平均中的处理，不将其擅自补为0。

主文Finding2报告Gemini单屏任务平均召回81.41%、精确率56.85%；Seed1.5-VL精确率75.7%、召回27.07%。前者更需过滤误报，后者可能漏掉大量问题。这里是跨任务平均，不能写成每类或每张页面的效果。

### 序列语义检测与提示策略

表2中序列F1最高Gemini24.94%，GPT-5为19.43%，最低Seed1.5-VL为1.92%；全模型平均11.44%。主文§4.2指出最容易召回的前20项中85%是简单数值不匹配；这只是小子集的诊断观察，不是全体数据85%都是数值错误。促销信息在付款流程中消失等需要跨页记忆的问题更困难。

表3只在Gemini与Seed1.6-Vision比较四类提示，不是对全部9模型逐项消融。单屏平均F1的默认零样本结果分别66.79/64.93；自修正66.89/63.94；细粒度视觉提示FGVP为67.08/66.21；一例CoT为67.39/67.41。相对默认，后者分别增加0.60、2.48个F1数值点。未报告相应统计检验，不能由此证明所有提示优化无效或任何训练方案都有效。

## 错误分析与局限

**作者实际观察：**Gemini单屏错误分为6类，图7给出轻微缺陷29.5%、幻觉24.5%、含糊判断14.9%、正常边缘裁切12.4%、类别混淆10.0%、设计意图不清8.7%（主文第8页）。这是模型错误分布，不是数据集真实缺陷类别比例。轻微裁剪漏报、卡片空白误报和可滚动内容误报，分别对应细粒度视觉、设计语义和交互上下文不足。论文没有单独列全面Threats to Validity段落；研究总结强调这些能力瓶颈，不应把下面的外推限制全部冒充作者明确承认。

**我们的观察与复现边界：**①截图任务排除了主动交互，模型不知道滚动是否能显示余下内容，需要猜设计语义；不能代表带布局树与操作验证的系统。②合成图用于分类检测合理，但不能评价操作复现、根因或修复。③中文商业应用及两次运行的模型快照不代表所有语言与当前所有模型。④标签的规范差异、提示例外不完全一致、序列judge与匹配细节缺失，影响复现与结果解释。⑤框标注存在，但主表未报告独立框定位指标，不能从分类F1推导定位准确率。⑥无开发者确认/修复统计；此处是标注显示问题而非已提交的新bug报告。

## 和我们课题的关系

### 与 UX testing 的关系

直接覆盖遮挡重叠、溢出、裁剪和省略等显示候选，可作为检测任务定义、正负例构造与误报分析的素材。对UX-Agent最有帮助的是明确“可滚动容器的边缘裁切”和“真实内容缺失”的边界：只看截图可能混淆，可用布局树和主动滑动提供额外证据。但本文没有实现这条主动验证链路，也没有证明滑动能修复或消除问题。

### 与 GUI testing 的关系

提供显示预言的评测基准及跨页面信息呈现一致性任务，与GUI功能探索、代码引导、回归维护互补。它不评价Agent是否进入正确状态、动作是否完成或整个应用被测得多充分。若借其数据评价新系统，需要保持单屏/序列、合成/真实和分类/定位各自口径，并检验采用的设计规则是否适合本课题。
