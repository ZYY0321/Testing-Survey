# OS-Genesis：先与界面交互，再反向合成训练 GUI Agent 的任务与轨迹

## 一页读懂

| 问题 | 本文的回答 |

## 一段话介绍

OS-Genesis 把 GUI Agent 的训练数据收集顺序反过来：先在手机应用或网站里实际操作，知道一个控件会造成什么变化，再让模型想这次操作可以服务于哪个更完整的用户目标。之后，GPT-4o 按这个目标重新走一条多步路径，形成训练轨迹；另一次 GPT-4o 评分根据完成程度与动作连贯性给轨迹打 1–5 分，训练时更常抽到高分轨迹，也不完全丢弃有价值但尚未做完的路径。论文用训练后的在线任务成功率证明数据价值。它回答了“任务不一定要人预先写”的问题，但没有为应用生成“正确行为必须怎样”的业务断言，也没有注入产品故障来测测试器。

## 关键术语与阅读前提

- **轨迹（trajectory）**：一次交互中的状态、动作及推理记录；这里还配高层任务。见[状态与操作](../glossary.md#state-graphs)。轨迹可训练操作能力，但不是天然具备预期结果的完整测试用例。
- **高层/低层指令**：高层目标例如收藏某道菜；低层描述例如打开菜谱详情再点收藏。后者帮助训练逐步规划。
- **可访问性树（accessibility tree / a11ytree）**：以文字结构表示屏幕控件的属性和层次，见[控件树](../glossary.md#view-hierarchy)。本文既用截图又用这类结构信息，不是只看图。
- **反向任务合成（reverse task synthesis）**：从已经观察到的动作变化构造任务，不是给定任务后直接生成动作，也不是把一整条随机路径原封不动改写成一句话。
- **TRM（Trajectory Reward Model，轨迹奖励模型）**：本工作以 GPT-4o 提示评分为主，评价任务完成和轨迹连贯性；不是另外训练好的应用故障 oracle。
- **SFT（supervised fine-tuning，监督微调）**：用收集的示范训练模型预测思考/动作。本文虽使用奖励分数，但主要是按分数采样后做监督训练，不能称为在线强化学习。
- **SR / Type**：SR 是对应任务的成功指标，Type 是动作类型与标注一致的比例。离线数据的动作匹配与在线完整任务成功不是相同分母，见[指标](../glossary.md#metrics)。

## 动机

论文 §1（PDF pp.1–2）指出，人工收集要同时写任务、执行全过程、保留状态并标注动作，费用高。自动收集常先根据首页和任务示例编指令，再尝试执行；首页看不到的功能容易漏掉，编出的任务也可能不符合当前环境。即使任务合理，执行模型仍会中途走错，得到不完整轨迹。

作者的关键选择是先获得环境中真正发生的状态转移，再以其为依据提出任务。这样能减少“任务想得合理但应用根本做不到”的脱节。它并不意味着由一次点击就证明任意高层任务一定能完成：高层任务仍由模型联想，随后还要实际执行并评分。

## 贡献

按 §1（PDF p.2）的作者贡献归纳：

1. 将 GUI 轨迹收集从预设任务驱动改为交互驱动，提出从局部状态转移反推任务的机制。
2. 实现从环境探索、任务合成、轨迹执行到奖励采样和监督训练的数据流水线。
3. 在移动和 Web 的在线/离线评价中比较数据训练效果，并分析多样性、奖励与数据规模。

核心属于 **method**，作用是训练数据生成。本文使用既有 benchmark 做评测，不能因此标成提出了新的应用缺陷 benchmark。

## 方法

整体过程是：**规则探索 → 记录真实转移 → 反推局部指令与高层目标 → 按目标重新执行 → 轨迹评分 → 按分数采样做监督训练**（§3–4，PDF pp.3–6）。

### 1. 先探索控件，产生真实变化

在 Android 模拟器和 Chrome 环境中遍历交互元素，使用点击、输入和滚动等动作。探索主体由规则完成，但输入框内容由 GPT-4o 根据上下文生成，因此不能把整个探索绝对称为不用模型。每次保留前态截图、动作和后态截图的三元组（§3.1，PDF pp.3–4）。

正文没有给出一套保证覆盖全部功能的遍历充分性证明，不能把“遍历交互元素”理解为完全探索所有输入、账户、权限或业务状态。

### 2. 从局部动作生成候选任务

GPT-4o 接收动作类型、前后截图、应用名；点击时还给被操作元素的红框。先生成该动作对应的局部描述，再分析可能后续操作，最后提出可在当前环境实现的高层目标。移动提示明确要求保留文件名、时间等关键细节，并输出局部指令、分析和高层指令（§3.2、Appendix C / Prompt 14，PDF pp.4、14–15、19）。

例如原文解释：点击打开下拉菜单，可以反推“显示选项”的局部目标，再联想到配置应用设置。后一目标并非仅由截图差分机械恢复，而是融合模型的语义和常识；这是它的扩展能力，也是可能幻觉的来源。

### 3. 不是直接拿随机路径训练，而是重新执行目标

合成的高层目标再交给 GPT-4o，在环境中逐步执行，形成含任务、截图/树、低层思考和动作的完整轨迹。初始局部交互主要为任务提供依据，不等于最终训练轨迹的所有步骤已经存在（§3.2，PDF p.4）。

图3 的原文移动例子是收藏 Broccoli 中的 Avocado Toast with Egg 菜谱：打开应用、进入详情、点击收藏，作为完成路径；另一条日历任务只完成部分操作，但仍有可学习片段。这里收藏成功是用户任务完成，不是对收藏功能没有 bug 的独立证明。

### 4. 分级评价，保留部分完成轨迹

TRM 读取高层目标、整个动作/低层思考历史以及最后三个状态截图，评价完成程度与连贯性，给 1–5 分。训练采样概率为某轨迹分数除以全部轨迹分数之和。因最低分为 1，算法没有把低分轨迹自动降为零概率，也没有只保留完整成功轨迹（§3.3 / Algorithm 1、Appendix F，PDF pp.4–5、15、25）。

Prompt 21 给每档评分的解释，允许复杂任务中有价值的未完成尝试获得更高评价。因此，TRM 不是二元“成功即真、失败即假”的标签器，更不是应用故障真值。它主要看到轨迹尾部图像，对早期局部异常的视觉复核有限。

### 5. 用轨迹训练规划与动作两种输出

规划训练输入高层任务、当前状态与历史，预测低层思考和动作；动作训练给定低层思考，再预测动作。训练后的模型以逐步思考/动作形式执行。实现使用 InternVL2-4B/8B 和 Qwen2-VL-7B-Instruct 做全参数监督微调（§4.1–4.2，PDF pp.5–6）。

## 核心技术：任务生成、轨迹质量和应用正确性是三回事

**任务来源改变了，但任务还需执行。** 反向生成依托真实交互，降低不支持任务的比例，却没有保证高层推断总可行。重新执行和奖励模型负责减少训练噪声，受执行模型上限约束。

**奖励用于数据利用，不承担软件 oracle。** 例子中“点收藏后出现收藏态”可提高完成分；若这个 APP 没有真正持久化收藏，仅凭尾部图像仍可能给高分。这是针对本研究用途的分析，不是作者报告的已发生失败。

**部分失败轨迹也能训练动作。** 只用完整成功轨迹会丢掉前段正确操作，作者用分级采样保留它们。它与测试中的缺陷报告保留并非同一个机制：未完成可能来自模型错误、不可达目标或应用问题，本文没有将它们诊断成产品故障。

## 实验

### 数据、评价与预算

| 设置 | 所读正式稿的具体协议 | 解释边界 |
|---|---|---|
| 合成训练数据 | Task-Driven 和 OS-Genesis 各用 1,000 条轨迹；Self-Instruct 用 1,500 条（§4.2，PDF p.6） | 相同轨迹数不等于相同生成费用/动作数。正文这处平均长度为 6.4 步，附录 G 又按不同方法/平台给出各自均值，不能当每组统一长度 |
| AndroidWorld | 原有 116 任务/20 应用；应用不可用后实际评 112 任务，NaN 重试后仍不完整记失败（Appendix A，PDF p.14） | 这是在线完整用户任务成功，不是缺陷检出。完整重复次数/方差未清晰披露，不据分数反推重复次数 |
| AndroidControl | 论文描述 7,708 个任务、1,412 条轨迹；用截图、树和历史，坐标距标注点不超过屏宽 14% 视为正确（Appendix A，PDF p.14） | 高层/低层是输入条件区别，仍以离线标注动作评价；不能把 high-level SR 当在线全流程通过率 |
| 应用重叠 | 正文称 AndroidControl 覆盖 833 应用，其中 20 个在合成时出现过（§4.3，PDF p.6） | 提供跨应用泛化证据，但不是训练平台与全部测试数据完全独立的证明 |
| WebArena | 每模板一次，共 241 次，而非所有 812 个任务全部执行（Appendix A，PDF p.14） | Web 只作为跨环境补充，不替代移动缺陷实验 |
| 模型和训练 | 生成/执行/主要奖励模型为 GPT-4o；训练用三种开源视觉语言骨干，8×A100 80GB 全参数微调（§4.1） | 训练硬件明确，但未据此补猜学习率、训练时长或总美元成本 |

比较对象包括：零样本操作；从初始截图和示例生成任务后执行的 Task-Driven；在其基础上用三个任务作上下文示例再扩任务的 Self-Instruct。它们不是另外一组应用缺陷检测器（§4.2、Appendix E）。

### 移动主结果：同一骨干比较训练数据

以下为 Table 1（PDF p.6），单位 %；最后一列属于离线 high-level 动作评价。

| 骨干 | AndroidWorld：零样本 / Task-Driven / Self-Instruct / OS-Genesis | AndroidControl-High：Self-Instruct → OS-Genesis |
|---|---|---|
| InternVL2-4B | 0.00 / 4.02 / 7.14 / **15.18** | 24.95 → **33.39** |
| InternVL2-8B | 2.23 / 4.46 / 5.36 / **16.96** | 23.43 → **35.77** |
| Qwen2-VL-7B | 0.89 / 6.25 / 9.82 / **17.41** | 39.36 → **44.54** |

同表 GPT-4o/M3A 的 AndroidWorld 为 23.70%。所以 9.82→17.41 是相对选定 Self-Instruct 基线改善 7.59 个百分点，不是超越 GPT-4o，也不是当前最新模型排行榜。

Qwen 的 AndroidControl-Low SR 为 74.17%，动作类型匹配为 90.72%；Self-Instruct 对应 71.51%/89.73%。动作类型对不意味着坐标、文字输入和整体任务都对，不能只拿 Type 当成功率。

### Web、奖励、规模和数据质量分析

- **WebArena（Table 2，PDF p.7）：** OS-Genesis 在三个骨干上的总体成功率分别 7.88%、9.96%、10.79%；GPT-4o 零样本 16.25%。支持合成数据对这些骨干的作用，不是网页测试检错成绩。
- **奖励消融（Figure 5，PDF p.8）：** 比较不评分均匀使用、只留完成轨迹的二元 labeler、分级 TRM；后者尤其改善高层和在线任务。图无逐项数值表，本记录不从雷达图估读精确增幅。
- **数据规模（Figure 6，PDF p.8）：** 轨迹从少量增加到约 1,500 时总体上升并趋饱和；作者认为骨干能力、探索范围和 GPT-4o 执行上限共同约束收益，不能推成样本越多永远越好。
- **多样性（§5.1、Appendix G）：** 用 Sentence-BERT 嵌入的平均余弦距离，比较指令和轨迹描述多样性；这是语义描述的代理指标，不直接证明功能覆盖或独立缺陷数。
- **奖励一致性（Tables 5–6，PDF p.16）：** GPT-4o 与 Qwen2.5-VL-72B 的 Spearman 相关为移动 0.729、Web 0.788；TRM 与人工评分相关为移动 0.813、Web 0.798。分别用抽样轨迹检查，相关性不是每条评分都正确，更不是应用 bug 判定精确率。
- **人工数据比较（Figures 7–8，PDF p.9）：** 区分人写任务再由模型执行，与完整人工示范两种条件；OS-Genesis 对完整人工数据仍有差距，作者报告相对其平均表现保留超过 80%。这不意味着任何数据量或应用条件下达到人工质量。

本文未做产品新缺陷的报告、确认或修复统计，不填造出的 bug 数。

## 局限

### 作者明确承认

Limitations（PDF p.10）列出：数据构造依赖 GPT-4o；训练/评价同时使用图像与文字结构信息；完整轨迹数量受执行模型能力限制。作者对未来开源模型的期待属于当时讨论，不能据此判断 2026 年所有开源模型仍不可用。

### 我们根据证据提出的边界

1. 高层任务仍由模型联想，尾部图像与轨迹评分不构成独立规格；不能直接认证业务结果正确。
2. 离线坐标容差、在线模板抽样和实际可用任务数影响成绩含义，不能与全基准、严格坐标或多次成功机会混比。
3. 主文与附录给出若干数据规模/均值，但未清晰披露完整生成预算、失败候选率和在线多次重复协议，不能仅凭效果表证明全流程更省钱或稳定性充分。
4. “无需人标轨迹/预写任务”是数据收集方式，环境、动作接口、提示、模型和评价器仍由研究者准备。

## 和我们课题的关系

### 与 UX testing 的关系

间接支撑页面与操作场景来源，可借局部交互反推“在哪个容器内向哪个方向滑动”等候选目标。现有 UX-Agent 以截图提出截断候选，再结合布局与滑动复核；本文既没有判定截断，也没有说明滑动后仍不可见是否是缺陷。若借其轨迹构造，要另保留正常露边、真实不可恢复截断与滑动失败等真值，不能让 TRM 代替 UX 判错。

### 与 GUI testing 的关系

最直接的启发是任务来源：可以先观察环境支持哪些行为再生成候选意图。但要把训练轨迹升级为测试，需要前置条件、输入变化、检查依据及独立的正常/故障评价。其论文故事围绕数据质量与训练后的任务表现；软件测试研究则还须证明这些新增测试是否揭示错误，不能照搬成功率当缺陷发现率。
