# GenA11y：用规范分解和页面证据检测网页可访问性问题

## 一页读懂

| 问题 | 本文的回答 |
|---|---|
| 研究什么 | 网页是否违反WCAG可访问性规范，尤其是图片替代文字、链接含义、标题等需要理解内容语义的项目。它不是全站自主探索器，也不是只看截图的通用布局缺陷检测器。 |
| 旧方法的不足 | 规则工具能查出“图片没有替代文字”，却难判断“文字虽然存在，但是否准确描述图片”；直接把整页HTML交给模型又缺少外部CSS、图片和渲染证据。 |
| 新增什么 | 先把规范分为可静态检查、需动态交互检查等类别，再针对37项准则分别提取相关DOM、计算后样式和必要截图，由37个定制提示的分析器检查。 |
| 输入与输出 | 输入网页URL；输出违反的准则、具体元素、原因与修改建议。37个分析器是检查任务分工，不是37个自主操作智能体。 |
| 怎样评价 | 已知/注入缺陷数据测召回；12个真实网站的模型报告经两位作者核查测精确率；另外比较30站的准则类型覆盖、重复运行、消融和成本。 |
| 主要结果 | 主实验516/589个已知问题被找到，召回87.61%；真实报告3122/3302有效，精确率94.5%；30站相对五工具并集额外237个“网站×准则”组合。 |
| 最重要边界 | 没有全面探索点击、键盘和读屏状态；总体精确率受大量尺寸/对比度问题加权，不能据此称文字截断、重排或每项准则都达到94.5%。 |

## 一段话介绍

网页可访问性测试不仅要判断界面是否显示正常，还要检查用户能否理解和使用其内容。例如，图片有替代文字并不意味着盲人用户能获得正确的信息，链接显示“更多”也未必能独立说明去向。GenA11y把WCAG规范作为判错依据，按每项准则挑选页面证据，再让GPT-4o做结构与语义判断：检查图片时提供实际图片及其替代文字，检查链接时补上相关上下文，检查缩放后的文字时提供前后截图。正式论文以已知缺陷、真实网页人工核查、消融和重复运行评价这种分解方式。它对UX oracle的价值是展示“规范→相关证据→语义判断”的设计，而不是证明纯截图模型能够可靠判断所有显示问题。[正式出版页](https://doi.org/10.1145/3729371)与[FSE Research会议记录](https://conf.researchr.org/details/fse-2025/fse-2025-research-papers/54/Enhancing-Web-Accessibility-Automated-Detection-of-Issues-with-Generative-AI)均确认其为FSE2025研究论文。

## 关键术语与阅读前提

- **可访问性（accessibility，a11y）**：使包括残障用户在内的人能够感知、理解和操作软件。本文同时涉及读屏语义、输入标签、视觉对比度等，不能全部解释为遮挡或溢出。
- **WCAG与成功准则（SC）**：WCAG是一套网页可访问性规范；SC是可供检查的具体要求。本文使用WCAG2.2，并按自己的分析把86项分为37项静态、45项动态、4项不可测试。这个分类是本文建模选择，不是当前规范机构对全部自动化能力的最终划分。见[术语解释](../glossary.md#wcag-evidence-analyzer)。
- **DOM（文档对象模型）**：浏览器中页面元素的树状表示。检查DOM可以获得链接、图片、标签及其父子关系；它不同于只读一张截图，也不等于分析后台业务源码。
- **计算后样式**：浏览器合并行内、外部样式和脚本影响后得到的实际CSS值。本文用`getComputedStyle()`读取颜色、字体等，避免只看HTML漏掉关键证据。
- **ARIA / accessible name**：ARIA是帮助辅助技术理解控件语义的角色与属性；可访问名称是读屏等技术用于识别控件的名称。页面可见文本、HTML属性与最终可访问名称可能不同。
- **精确率、召回与准则类型覆盖**：精确率问“报告中多少是真的”；召回问“已知问题中找到多少”；本文类型覆盖按“某网站的一项准则至少有一个有效报告”计数，既不是网页覆盖率，也不是所有缺陷实例召回。

## 动机

第2节用作者实验时的OpenAI首页说明问题：规则工具WAVE只确认一个缺失表单标签错误，却留下79条需要人工判断的提醒。页面研究卡片的图片是装饰图，但替代文字重复了旁边的标题，导致读屏重复播报。属性存在性检查不会自动知道这张图是否传递独立信息，所以仍需要语义判断。这里应理解为论文采样时期的具体例子，不能当成对该网站当前版本的检测结论。

直接提示模型分析完整HTML也不理想。作者在五所大学首页的预备研究中发现：输入冗长，外部CSS中的实际颜色/字体不可见，图片内容也不能由普通URL文本自动代替；模型还会集中报告少数熟悉准则，或在上下文缺失时误判。本文据此提出按规范拆分，而不是把所有页面信息和所有准则合在一次问答里。

## 贡献

作者在第3页明确列出四项贡献：研究WCAG准则的可检测方式；系统研究生成式模型检测网页可访问性问题；实现并公开GenA11y；以三类数据来源及五个既有工具评价有效性和效率。核心贡献记为 **method、empirical**：方法包括准则驱动证据提取和定制语义分析，实证包括覆盖、误报及成本分析。虽然扩充了既有测试网页并公开数据，不把它自动提升为覆盖全部GUI任务的统一benchmark。

## 方法：输入证据和规范怎样连接起来

### 1. 先限定哪些问题由当前工具负责

第3节把86项准则按检测方式划分。37项归为静态检查范围，即不需要像爬虫那样持续生成鼠标/键盘事件来判断交互行为；45项需要动态分析，例如焦点顺序、键盘陷阱和字幕；另外4项被作者归为不可测试。工具只实现第一组。

“静态”不能理解为完全不启动浏览器或只检查源码字符串。作者会加载并渲染页面、捕捉全页截图；检查文字缩放还比较200%缩放前后的截图，截图采集可以滚动。其排除的是动态交互状态探索和行为验证，而不是排除一切运行时采集或页面变换。因此，本笔记将其归为GUI oracle，DOM/样式是证据来源，不将它描述成源码风险定位方法。

### 2. 每项准则先定义需要哪些元素与上下文

第4.1节依据WCAG的满足技术、常见失败和测试规则人工制定提取范围，必要时参考HTML、CSS和可访问性API映射标准。例如，图片不仅可能是`img`，也可能由`picture`、CSS背景图或带图片角色的元素表示，提取器不能只搜一种标签。

浏览器通过Selenium加载URL，等待`document.readyState`和加载时间信息等信号，再分别收集：相关元素及行内属性、通过浏览器API得到的实际样式、所需的图片或截图。颜色对比检查要知道前景色、背景色和字体尺寸，因为大小字体要求不同；只给HTML里的文本不能完成这项判断。

链接含义检查还要补语义上下文。本文针对SC2.4.4提取链接及相邻、祖先元素，并依照相关技术最多向上遍历5层寻找有意义的上下文。显示“阅读更多”的链接在单独看来可能含义不足，但放在一段明确介绍目标内容的句子里可能合规。提取规则在这里直接影响误报，而不只是减少token。

### 3. 37个分析器对应37项准则，不共享一个全局探索目标

每个分析器接收四类内容：检查任务说明、准则及常见失败/测试规则、相关页面证据、结构化输出要求。系统把模型设为可访问性专家，但真正可审计的判据来自准则和提取证据，不能把角色设定本身当成可靠性保证。

作者没有使用few-shot示例。预备研究发现单个例子易把判断收窄到类似失败，多例子又增加token并分散注意力，因此采用规范说明。输入可以同时包含HTML、相关CSS、对应JavaScript函数，以及元素或全页图像；并非所有37项都只看截图，也不是全部都只读结构。

输出JSON包括总体是否违反、违反元素的`outerHTML`、原因和建议。它提供可定位的报告，**未实现修复、执行修复后复测或用户任务达成验证**。作者选择`gpt-4o-2024-08-06`，温度0，并并发处理不同准则/API等待；没有训练新模型，也没有让分析器自主决定下一页点击。

### 4. 37项实际涵盖什么

下面完整列出表1的37项，并按需要理解的问题合组。**合组是本笔记的教学整理；“检查内容”解释准则目标，不能冒充论文为每一项都公开了同等细致的提取器实现。** 正文详写了图片、链接、样式、缩放和标题等例子；其余项目的逐准则提取规则主要指向配套实现，本文没有复现或逐行审计全部实现。

| 方向及准则编号 | 具体要判断什么、模型为何需要这些证据 |
|---|---|
| 图片及替代文字：1.1.1 | 图片的替代说明是否存在、是否准确、装饰图是否不应重复播报；需要图片内容、替代文字和相邻语义。不能把所有图片都要求有长描述。 |
| 信息结构及表达：1.3.1、1.3.2、1.3.3 | 标题/列表/标签关系是否正确，阅读顺序是否有意义，指令是否只靠位置或感官特征表达；需要DOM关系、文本和部分视觉证据。样式像标题但没有标题语义就是本文检测例子。 |
| 方向与输入用途：1.3.4、1.3.5 | 内容是否不必要地限制显示方向，常见输入目的是否可被辅助技术识别；被列入范围不表示工具做过所有旋转和交互状态测试。 |
| 颜色与对比度：1.4.1、1.4.3、1.4.6、1.4.11 | 是否仅以颜色区分信息，普通/增强文字对比度和非文本对比度是否足够；颜色、字体、形状及上下文都可能影响判断。正文明确把计算所需值交给模型，而不是声称对所有项目均用确定性数值检查替代模型。 |
| 缩放、重排和文字呈现：1.4.4、1.4.8、1.4.10、1.4.12 | 文字放大、空间重排或间距改变后，信息是否仍可读取；SC1.4.4明确采集200%缩放前后全页截图。这一组与截断/溢出最接近，但正文没有逐项展示完整的主动找回丢失内容机制。 |
| 图片中的文本：1.4.5、1.4.9 | 应当能由真正文本表达的信息是否被做成图片；两项的适用条件不同，不能把“图里有字”一律等同违规。 |
| 音频、时限和运动内容控制：1.4.2、2.2.1、2.2.2 | 对相关控制及页面证据进行检查；不能扩展成视频字幕内容正确性、所有运行时超时和自动更新序列验证。 |
| 页面和站点导航：2.4.1、2.4.2、2.4.5、2.4.8、2.4.10 | 绕过重复块、页面标题、多种到达方式、当前位置和章节标题是否满足要求；这是可访问性导航语义，不是生成最优页面跳转路径。 |
| 链接、标题及标签含义：2.4.4、2.4.6、2.4.9 | 链接是否靠上下文或自身就能说明目的，标题/标签是否描述对象；2.4.4允许上下文，2.4.9要求更强，必须区分。 |
| 可见标签和点击目标：2.5.3、2.5.5、2.5.8 | 可见标签是否包含在可访问名称中，点击目标是否满足相应尺寸要求；不意味着所有小控件都违规，例外条件仍来自各准则。 |
| 语言、缩写与输入提示：3.1.1、3.1.2、3.1.4、3.3.2 | 页面/局部语言标注、缩写解释和表单标签或说明是否适当；主要依赖结构和内容语义。 |
| 可预测变化与语义兼容：3.2.2、3.2.5、4.1.2 | 输入/请求变化的相关规定，以及控件名称、角色和值；工具静态范围不能证明实际所有事件处理行为合规。 |

合计1+3+2+4+4+2+3+5+3+3+4+3=37。这个范围比单一布局oracle广，但37项“支持”不等于37项都获得充分、均衡的独立评测。

### 5. 用一条具体检查流程理解方法

论文原始例子是“Read more”链接及其相关上下文（第9–10页）。系统先定位具有链接语义的元素，收集文字、目的地址和相关祖先/兄弟内容，再把SC2.4.4允许利用上下文的规则交给模型。模型需要判断这些证据能否说明链接目的，输出具体元素和理由。若改查SC2.4.9，就不能仍用同样宽松的上下文标准。该例说明方法重点在**判据与证据的对应关系**，并非单纯“让LLM逐项打勾”。

## 实验：各项证据的对象与分母

### 数据来源和负例边界

| 数据 | 如何建立、用于回答什么 |
|---|---|
| Da：扩充Accessibility Tool Audit | 原始142个手工构造测试网页；排除不对应当前准则或过时等21项，剩121，再补23个网页到144。主表以144个已知问题计数。新增网页覆盖原先缺少的8项准则。用于召回与消融。 |
| Dm：Ma11y | 在真实网页上程序注入可访问性问题；主表445个问题。与Da共同用于召回。它不是自然发生、开发者确认的新缺陷集合。 |
| Dr：真实网站 | 30个网站，来自先前研究，覆盖28个类别；用于准则类型覆盖和性能。精确率从中按报告数量/类型各占50%的排序分层抽6站，再增6个模型发布后出现的网站，合计12站。全文说36个真实网站，来自30+6，不能理解为全部36站都做了同一种人工完整审核。 |

作者不把Da/Dm中“真值清单之外的报告”直接当误报，因为构造页或原始网页可能还有未标注问题。这是合理的真值边界，但意味着这两组主要证明已知正例找回能力，**没有均衡的正常页面负例集来评价所有准则的特异性**。真实网站的精确率来自对已报告元素核查；未报告区域没有完整穷尽标注，不能推得真实站点的召回率。

### RQ1：已知问题找回多少

主实验表2：Da为127/144，Dm为389/445，合并516/589=87.61%。最强既有工具IBM为225/589=38.20%，差为**49.41个百分点**，不是相对提升49.41%。五个比较工具为IBM、QualWeb、Axe-Core、A11yWatch、WAVE；Access Continuum因拿不到API key未纳入。

分母包含动态范围的缺陷。正文称Da有17、Dm有49个动态问题不支持，另外Dm漏7个静态问题；按该解释剩余可支持问题为523个、找到516个。但这是依据正文做的范围内重算，**不是论文另行报告的统一实验指标**，不替换原87.61%。部分规则基线能检出GenA11y没有处理的键盘/焦点项目，这也说明覆盖范围和单项检出能力应分开比较。

静态漏报例子包括：H5/H6级视觉标题与普通加粗文本相似，模型未认出“看起来是标题但DOM未采用标题语义”。总召回较高不能抹去细粒度视觉语义的漏报。

### RQ2：多找到哪些“类型”

30站上先合并五个既有工具的报告，再人工确认每一项准则是否至少有一个真问题。既有工具得到216个“站点×准则”有效组合，GenA11y覆盖其中198个，另增加237个组合，平均每站7.9个新增类型。237不是237种独立WCAG准则，也不是237个开发者确认bug。

GenA11y并非完全取代规则检查：漏掉的既有类型中，15个与信息关系/对比度有关。元素label的`for`不指向有效输入框、少量低对比元素淹没在大量正常元素中等，规则扫描可能比模型更稳。

### RQ3：真实报告是否正确

两位作者独立检查12站的每条报告，要求准则判断、元素和理由对应，并且元素实际可见；分歧讨论解决。GenA11y报告3302个问题，3122个有效，精确率94.5%；其中旧网站1911/2007=95.2%，新增网站1211/1295=93.5%。既有工具总表包括Axe-Core33/33、WAVE592/603等，报告范围和数量不同，不能把精确率一列当成同任务胜负。

总体数字受类别频率明显影响：两个尺寸项目共有639条，最小/增强对比度共有1135条，合计1774/3302，超过一半。某些与显示研究相关的项目样本非常少：重排12条中10真、文字缩放16条中14真、视觉呈现17条中9真；页面标题5条只有1真。不能将94.5%移植为重排、截断或语义标题项目的可靠性。

典型误报是过度严格：把“OpenAI”标题要求改为很长的说明；认为链接必须加下划线，忽略旁边的箭头或边框已经提供非颜色提示。规范例子被模型当成唯一允许设计，是值得对比的oracle错误来源。

第7节报告跨工具5124个问题人工审核有122处分歧，kappa为0.745；重复精确率审核1643个问题有57处分歧，kappa为0.721。这些是标注一致性，不是模型准确率，也不能据此宣称用户真实困难全部被覆盖。论文没有给出开发者接收/修复数量或残障用户验证实验。

### RQ4–5：稳定性与消融

温度0仍重复5次。新增6站精确率范围92.9%–93.7%，共有1142个报告在5次都出现；主结果来自单次运行，不是取5次最佳。报告身份用元素outerHTML对齐，不能自动等同对页面语义变化的不变性。

Da消融：直接HTML+基础提示找57个；加证据提取找93个；仅加详细规范提示找104个；二者结合找127个。提取组件不只是压缩文本，还补齐实际颜色/图像；规范提示说明什么情况构成违反。该消融支持二者互补，但未分离图片输入、祖先上下文、确定性规则和模型推理各自的独立贡献，也未比较其他模型或专门的视觉主动复核方法。

### RQ6：时间、成本和配置

Selenium采集，GPT-4o，温度0，多进程/线程并发，实验机器AMD Ryzen7、32GB。30站平均240秒、约191.2万token、4.78美元/站；平均每分析器约5.17万token。采集25–65秒；分析阶段示例67–402秒，网页越大越贵。这是**当时配置及计费下的历史实测**，不是当前模型价格，也不包含全站所有路径探索成本。并发解释了为何总时间不能由37次串行简单相加。

## 局限

**作者明确承认的范围和威胁（第6、19–20页）**：未做动态准则，需要爬虫、键盘/鼠标等交互；模型仅GPT-4o，其他模型泛化是推测；可能有实现/第三方库错误；真实站点与训练内容可能重叠，所以补了发布后网站；未来还需要开发者研究验证报告是否真正帮助理解和解决问题。

**本笔记基于证据的观察**：首次网页存档晚于模型发布不能严格证明训练数据完全隔离；作者主观判断为人工真值，未报告盲法、外部无利益关联专家复核或用户任务成功率；总体精确率混合多类、样本不平衡；主要已知正例数据不足以说明所有正常设计的误报率；大输入和按准则重复证据可能成为规模化成本来源。静态快照无法证明隐藏内容真的不存在或操作后能否恢复，不能凭本文直接宣称已解决主动UX复核。这些是后续比较问题，不是已经确证的研究空白。

## 和我们课题的关系

### 与 UX testing 的关系

直接帮助建立**规范与证据对应的oracle**：图片语义、标题/链接、颜色、大小、缩放与重排等不同问题，应有不同证据，不宜让同一个通用提示笼统判断“页面是否有UX问题”。对文字截断而言，SC1.4.4已有缩放前后截图证据；可借鉴其分项、定位元素和报告理由，但不能将读屏替代文字错误当作遮挡/重叠的同类缺陷。

与[UI-Lens](xiang2026uilens.md)不同，本文以WCAG规范和DOM/计算后样式为主要组织依据，提供检测方法；UI-Lens以专家标注显示任务评价通用多模态模型。与[ReFLAIR](he2026reflair.md)不同，本文不以宽窄布局的功能等价和局部滚动/展开寻找组成闭环；ReFLAIR把候选缺失反过来变成操作目标，避免正常折叠菜单被误判。本文虽然会滚动截图或做缩放，不等于具备同类候选驱动验证能力。

### 与 GUI testing 的关系

它是“规范驱动、结构与视觉证据混合”的非崩溃oracle，不负责全局状态覆盖、自然语言任务导航或测试脚本维护。若与探索器组合，必须另行说明到达哪些状态、哪些准则在每个状态适用、是否引入交互复核以及如何评价新增收益；不能以串接一个探索agent就认定新的贡献已经成立。
