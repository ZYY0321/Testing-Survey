# AnTrap：在 Android 运行过程中注入异常，检验 GUI agent 能否恢复

## 一页读懂

| 问题 | 本文的回答 |
|---|---|
| 旧评测哪里不够 | 在正常环境完成任务，不能说明遇到弹窗、错点、错误历史或反复退回后还能恢复；给定静态坏截图也测不了后续状态变化。 |
| 本文新增什么 | STAR 四层十子类异常体系、可插入执行环路的陷阱工具箱，以及从 AndroidWorld 扩展的 236 个基础任务；另用强化学习分析哪些异常较容易学会应对。 |
| 输入与输出 | 输入用户指令、初始化手机环境和注入配置；agent 逐步看截图并操作，工具箱在指定层干预；输出任务轨迹、成功判定与正常/受扰动成绩差异。 |
| 怎样验证 | 16 个模型在正常及十类扰动下比较规则成功率，使用 Pass@3；两个 7B 模型分别在正常、单类陷阱和混合陷阱环境训练。 |
| 最主要结果 | Claude-Sonnet-4.6 从正常 74.2% 降至扰动平均 66.5%；GUI-Owl-7B 从 63.1% 降至 47.7%。单类针对训练明显改善部分单步异常，循环等跨步问题改善很小。 |
| 最重要边界 | 这是 agent 恢复/鲁棒性评测，**不是应用缺陷发现 benchmark**。陷阱可能修改观察、动作或历史，而非改坏应用内部代码；成功绕过异常也没有证明 agent 报告了产品 bug。 |

## 一段话介绍

AnTrap 研究的是手机操作 agent 在运行中受到干扰后能不能回到用户任务。它在 AndroidWorld 正常任务外包一层干预器：可以突然盖住界面，可以短暂给模型看旧截图，可以把即将执行的点击偏移，也可以连续拦截动作或把页面退回。作者没有让 agent 事先知道哪里会出问题，而是用相同任务在正常与受扰动条件下的成功率差异衡量恢复能力。四层十子类不是十种产品缺陷，而是沿“环境状态—模型决策—动作执行—多步过程”定位不同异常。正式全文进一步提供注入时机、历史保留规则、具体算子与训练实验，使其可用于分析一次模型失败究竟是当前观察问题，还是对跨步历史依赖不足。（§1、§3–5，PDF pp.1–8）

## 关键术语与阅读前提

- **[运行状态与交互历史](../glossary.md#state-graphs)**：当前页面是一帧观察，历史还包含之前截图、推理和动作。AnTrap 可使它们不一致，以检验模型是否只信当前画面。
- **[Grounding（控件定位）](../glossary.md#grounding)**：把“点保存”落实到一个坐标或编号控件。本文有意偏移坐标，测试 agent 是否发现执行效果不符合原意。
- **STAR**：State、Thinking、Action、Round，分别为状态、决策思考、动作和跨步过程四层；不是四个模型角色。
- **干预钩子（hook）**：在取图、给模型输入、派发动作等位置拦截数据；它是外围执行框架，不能描述成修改模型内部参数或直接编辑其隐藏推理。
- **[Pass@3](../glossary.md#metrics)**：给每项评测三次尝试机会的成功指标，不是每任务只运行一次的成功率；不能与单次基线直接排名。
- **GRPO**：Group Relative Policy Optimization，组相对策略优化。对同任务采样多条完整轨迹，以组内奖励差异更新策略；本文的奖励主要来自是否完成任务，不来自是否正确报告 bug。

## 动机

图 1 的四个实际场景说明作者关心的恢复：订酒店时遇全屏弹窗；添加工作电话时误把号码类型当成工作；调整闹钟音量时滑动没碰到目标；广告把 agent 引到别的应用。只记录最终成功或失败，无法主动、系统地控制这些异常何时出现。静态坏截图评测又会在下一步直接送回标准观察，不能说明 agent 实际能否修正偏离。（§1、图 1，PDF pp.1–2）

作者先做真实设备先导研究：600 个日常任务、30 多个 Android 应用，使用三个 GUI 模型记录截图、推理和动作；两名作者逐步标注，先对 150 任务开放编码，再用其余 450 任务迭代分类。这里的 600 是分类研究任务，不是最终 236 个基础评测任务，也不是训练池的另一个 600。（附录 B，PDF p.14）

## 贡献

按作者 §1 的贡献与实际实验归纳：

1. 将运行异常组织为四层十子类，覆盖环境扰动和执行过程中的认知/动作问题。
2. 提供动态注入环境和 236 个基础任务，使异常类型、内容和时机可配置。
3. 比较 16 个模型的受扰动表现，并以正常、单类陷阱、混合陷阱训练区分可学习的恢复与仍困难的跨步恢复。

贡献重点是 **benchmark 与能力诊断**；强化学习实验用于理解 benchmark，不等于提出通用的抗异常训练解决方案。论文未贡献自动发现真实应用 bug 的测试预言。

## 方法：一轮运行怎样发生

1. **初始化任务。** 在 AndroidWorld 的任务定义、初态和规则评估器基础上，人工新增 120 个场景，形成 236 个基础任务；指令和初始数据可随机化，每个新增任务经人工验证。（§3.3、附录 A.1，PDF pp.4、12）
2. **配置陷阱。** 选择十子类之一、触发概率、次数上限与内容来源。中心控制器将干预插在 agent 与环境之间，无需改 agent 推理代码。
3. **正常或受扰动观察。** 未触发时原样传递截图；触发后可能显示真实叠层弹窗、遮挡像素、旧截图或篡改文字。
4. **模型给动作。** 模型结合用户目标、截图和历史产生下一步；动作干预可在送往 Android Debug Bridge（ADB）的过程中改写坐标、动作类型或直接阻止执行。
5. **继续并评分。** agent 看后续状态，尝试恢复，直到结束或耗尽预算；原任务评估器判断是否完成目标。输出没有要求 agent 提交缺陷位置、根因或 bug 报告。（图 2、§3.3–4.1、附录 A，PDF pp.4–5、12–14）

## 核心技术详解

### 十类陷阱不是十种相同的注入

| 层与子类 | 正式附录给出的具体实现 | 判读重点 |
|---|---|---|
| 状态：外部中断 | TrapOverlay APK 接收 ADB 广播，显示权限、居中对话框、顶栏通知、全屏广告；92 条模板，也可由模型按当前应用生成内容，解析失败回退模板 | 部分是真实可交互叠层，不能全部归为图像编辑 |
| 状态：视觉遮挡 | 对控件或随机区域加模糊/色块；随机矩形可覆盖屏幕 10%–30% | 主要改变 agent 看到的像素，不必改变应用实际控件 |
| 思考：时间冲突 | 给决策模型看 N 步前截图，默认 N=3，或来自无关应用的截图；持久历史保留当前未扰动图 | 通过误导输入诱发错误，不是直接编辑模型隐藏思维 |
| 思考：视觉幻觉 | 利用控件树文字框，将标签替换为 Save/Delete 等反义词；有 24 对词，未知标签作字符打乱 | 模型可能在后续历史中保留被误导的决策 |
| 动作：定位偏移 | 送往设备前，触点横纵坐标各偏移 20–50 像素，正负随机 | 不是应用按钮坏了，而是实际点击偏离原意 |
| 动作：类型错配 | 点击、长按、双击相互替换；交换滑动起止点以反转方向 | 要从结果发现执行语义与计划不一致 |
| 动作：意图偏离 | 改点另一个控件，优先相反意义按钮；输入文字换成错误文本 | 可造成不可逆操作，任务仍可解的保证需依赖具体场景验证 |
| 跨步：状态僵持 | 连续 k 步丢弃 ADB 指令，k 从 1 到原步数预算四分之一内采样 | 暂时无响应由框架模拟，不自动等于 APP 内部故障 |
| 跨步：上下文打断 | 发 Home 或最近任务键，等待一秒，让新截图反映偏离 | 界面真的跳转，agent 需找回目标 |
| 跨步：循环 | 默认每两步插入一次返回键，直到陷阱预算用尽 | 注入持续时间与一次“陷阱事件”不是相同计数 |

依据 Table 2、附录 A.1 Table 5（PDF pp.5、12–13）。表中参数是本文实现，不是所有手机场景推荐值。

### 观察和历史保留，是状态层与思考层的关键差别

状态层把被干预后的观察视作当步现实，记录进后续历史；思考层只在当次决策临时误导输入，随后保留未扰动的观察及模型在误导下生成的决策，使 agent 必须发现自己的先前判断与后续证据冲突。动作和多步层又在实际执行接口介入，因此仅看“有没有弹窗”不能覆盖该框架。（§3.3、附录 A.1）

**原文存在待核实差异：** §3.3 说动作层将编辑后的实际动作记录到日志；附录 Table 5 对坐标/动作类型/意图偏离强调持久历史保留原先意图或响应，且附录 History Policy 的归纳措辞也不完全一致。可同时存在执行日志与模型可见历史，但原文未把所有存储通道逐项对齐。本笔记不替作者补成已核实接口；复现时应查代码和具体消息流。（PDF pp.5、12–13）

### 怎么保证注入测的是恢复，而非任务被彻底破坏

作者要求原任务可解、注入后仍可解、陷阱符合真实移动场景；人工验证初次有 91% 满足三项，不满足者修订后纳入。这个数字是数据验证比例，不是模型准确率，也不是形式化保证所有变异都保留可解性。（§3.4，PDF p.5）

默认每步独立以 0.16 概率触发，单个 episode 的事件上限为一次；只在原预算前 80% 触发，总预算扩为原来的 1.15 倍，给恢复留时间。未注入的轨迹最多重试十次，仍未触发则从报告排除，平均 1.3 次尝试即可注入。一次跨步事件仍可连续干预多个步骤，不能把“每轮一次”读成“只破坏一帧”。（附录 A.1，PDF p.12）

### 原文例子：删除多条支出记录

图 11–15 都围绕 ExpenseDeleteMultiple。正常 GUI-Owl-7B 能完成；第 5 步坐标偏移后，它像没出错一样继续并宣称成功，任务实际失败；被打断到别处后也可能过早结束。另有训练后视觉遮挡和状态僵持恢复成功的轨迹。它们展示恢复机制差异，**没有证明模型主动把误删、弹窗或遮挡识别成产品 bug 并提交报告**。（附录 C，PDF pp.23–24）

## 实验

### 协议、预算与比较对象

- 基础评测为 236 个随机化任务及各类扰动对应版本，以原规则评估器判断完成，报告 Pass@3 和相对正常成绩的下降；不是 236 个不同真实 bug。（§3.4–4.1）
- 开源模型通过 vLLM 运行，最大上下文 32,768，提示最多八张历史图；API 模型温度 1.0、最大输出 4,096 tokens。八个并行 Pixel 6 模拟器，Android API 33；任务初态 seed=30，陷阱 seed=42。（附录 A.2，PDF pp.12–14）
- 模型包括四个专有模型、GUI-Owl 系列、MAI-UI、Qwen3-VL 与 UI-TARS；主要对照是同模型正常/受扰动，不是和某个故障检测器比较。
- GPT 使用带编号控件的 SoM 输入，因此未评价坐标偏移；其平均列覆盖的子类与其他模型不同，不宜仅据平均列给“完全同条件”排名。人类也有不适用子类。（Table 3、附录 A.2）

### 主结果：正常能力并不等于恢复能力

| 模型 | 正常成功率 | 陷阱平均成功率 | 绝对下降 |
|---|---|---|---|
| Claude-Sonnet-4.6 | 74.2% | 66.5% | 7.7 个百分点 |
| GUI-Owl-1.5-32B-Think | 69.5% | 62.4% | 7.1 个百分点 |
| GUI-Owl-7B | 63.1% | 47.7% | 15.4 个百分点 |
| UI-TARS-1.5-7B | 29.7% | 21.8% | 7.9 个百分点 |

Table 3（PDF p.6）。这些是本文模型版本、运行框架和 Pass@3 条件下的结果。不同模型绝对掉分与原始能力相关，不能只用掉分小就断言鲁棒性最好。部分子类反而高于某模型正常成绩，也不支持“每个模型每类都退化”的强说法。

### 强化学习究竟训练了什么

在两个 7B 模型上用完整轨迹的二元完成奖励训练，组大小 G=8；人工核验的训练池为 600 个参数随机化任务，并声明排除测试重合。原环境和陷阱环境保持其他训练条件一致。（§5、附录 A.3，PDF pp.7–8、14）

主实验的陷阱训练是**每一子类单独训练一个模型，共十个专用模型**。Table 4 的各行 +Trap 不是同一个统一模型抗住十类异常，正常任务行则是这些模型的平均。图 3 是分层汇总，而非另一套全部混训成绩。

| GUI-Owl-7B 的评测 | 基础模型 | 正常环境训练 | 同类陷阱专用训练 | 支持的判断 |
|---|---|---|---|---|
| 正常任务 | 63.1% | 69.9% | 69.5%（十模型平均） | 两种训练都提高一般执行 |
| 外部中断 | 43.2% | 45.3% | 54.2% | 针对暴露提高 11.0 个百分点 |
| 视觉遮挡 | 57.6% | 58.9% | 66.5% | 提高 8.9 个百分点 |
| 状态僵持 | 42.4% | 42.8% | 44.9% | 增益较小，未消除困难 |
| 循环 | 35.6% | 36.0% | 36.4% | 增益仅 0.8 个百分点 |

Table 4（PDF p.8）。作者表中显著标记的含义是绝对提升至少五个百分点，**不是统计显著性检验**。

附录 D 另训练每底座一个混合模型，每轮等概率抽十种子类，其恢复增益明显弱于专用训练：GUI-Owl-7B 外部中断仅 46.2%，循环 36.0%，意图偏离还从 57.2% 变为 55.5%。所以本文更稳妥的结论是特定异常有针对训练收益，多步困难仍存在；不能写成已证明“任何训练都无法解决深层推理”。（Table 7，PDF p.15）

## 局限

**作者承认（Limitations，PDF p.9）：** 236 个任务无法代表所有 Android 场景；缺少对抗监督微调（SFT）比较；研究以诊断为主，不提供可扩展通用训练方案。

**我们的观察：** 模拟异常的分布与实际部署频率尚有差距；可解性依赖人工和具体操作后果，误改不可逆数据需特别检查；Pass@3、预算延长和特殊输入方式限制与其他研究比较；历史记录表述差异妨碍精确复现。主专用训练和混合训练的区别必须保留。没有故障报告真值，不能从规则成功率推得缺陷发现 precision/recall。

## 和我们课题的关系

### 与 UX testing 的关系

可借它模拟滑动未生效、坐标偏移、视觉遮挡和页面跳转，检查截断复核器是否把“动作没执行成功”错误当成不可恢复截断。当前候选→布局→滑动链路需要知道动作实际作用于哪一容器，而 AnTrap 展示了可控干预来拆解这类执行错误。但它的图像遮挡不自动是应用真实截断，任务完成也没有评价缺陷确认。若以其工具构造 UX 数据，还须增加正常露边负例、可交互状态和独立缺陷标签。

### 与 GUI testing 的关系

它为测试环境的动态干预与执行鲁棒性提供可借底座。要转成测试 agent 的故障发现评测，需区分应用异常、外部中断和执行器错误，并增加到达、触发、识别、证据和报告评分。保持任务可解很适合研究绕过/恢复，但真实产品 bug 也可能让目标无法完成；不能把可解性条件直接当通用缺陷数据的必要定义。

> — Abstract，PDF p.1。

## 原文摘录

> “each subcategory’s +Trap entry”
> — §5.3，PDF p.8。

此处紧接说明每类结果来自在同一子类训练和评价的模型，不能将 Table 4 读成统一模型。

> “exactly one trap event”
> — 附录 A.2，PDF p.14。

事件可能跨多步持续；它限制注入事件数量，不保证只干预一个动作。
