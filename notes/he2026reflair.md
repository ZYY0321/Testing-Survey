# ReFLAIR：通过滚动和菜单展开，验证响应式网页是否真的丢失信息或功能

## 一页读懂

| 问题 | 论文的回答 |
|---|---|
| 测什么 | 同一网页从宽屏变为窄屏后，原有信息和可操作功能是否仍能被用户找到和使用；不是把所有像素变化当错误。 |
| 为什么不能只看两张图 | 窄屏允许将导航折叠到菜单，或把内容移到当前视口之外。最初截图看不到，并不等于功能丢失。 |
| 方法新增什么 | 先从 DOM 与截图提取信息控件和可操作控件，记录点击效果，比较宽窄布局；对疑似缺失项继续滚动、让模型生成展开菜单的代码，再检查信息和功能等价性。 |
| 最直接的项目关联 | 已有的“候选异常→主动交互复核”方法。它既有目标明确的局部探索，也有根据补充观察撤销误报的 oracle，不能把加入滚动本身作为新研究点。 |
| 主要证据 | 主数据集24网页，报告 precision 80.49%、recall 95.31%，每网页3次取平均；扩展集36网页，84.62%/93.32%，每网页2次。 |
| 重要限制 | 主要为离线网页副本、点击与简单展开；复杂多步流程未建模。主集平均顺序运行3.23小时/网页，39.05分钟是并行化估算；时间性轮播和滚动吸附仍会误报。 |

## 一段话介绍

网页缩窄时，原来的横向菜单可能变成折叠菜单，屏幕上不再显示的内容也可能只是需要滚动才能看到。ReFLAIR 研究的是：如何区分这种正常适配与真正的信息、功能丢失。它从宽屏与窄屏布局的 DOM 和截图提取控件，对可点击项实际执行并保存前后变化，再寻找语义和功能相当的对应项。初次没有匹配到的控件成为后续探索目标：系统滚动寻找，或让模型生成打开折叠菜单的程序，找到后重新匹配，仍未找到才报告缺失。24个网页上，检测精确率为80.49%、召回率为95.31%；去掉探索后，误报显著增加。它说明主动探索不只用来增加覆盖，也可以为判错补充反证。但网页副本、参照布局、有限展开步数和动态时间状态共同限制了结果，不能把“搜不到”直接推广成一般性的不可达证明。

## 关键术语与阅读前提

- **响应式网页设计（RWD）与重排（reflow）**：同一页面随可用宽度改变布局。例如导航文字在宽屏并排展示，在窄屏收进菜单。重排本身是正常设计，不是缺陷，参见 [响应式重排与主动复核](../glossary.md#reflow-active-verification)。
- **视口（viewport）与 CSS 像素**：浏览器当前可显示页面的矩形区域及其布局单位，不等于设备硬件像素。论文主要比较1280×1024与320×1024 CSS像素，参见同一[术语说明](../glossary.md#reflow-active-verification)。
- **[DOM](../glossary.md#dom)**：网页运行时元素树，可提供文字、图片替代文本、位置与点击对象。这里使用结构信息不表示分析了应用后台业务源码。
- **信息控件与可操作控件**：前者承载可读文字或有替代文本的图像；后者可点击或具有鼠标事件。一个文字链接可以同时属于两类，两个集合不能机械相加为独立元素总数。
- **等价性**：布局、位置甚至控件外观可不同，但用户获得的信息与触发的功能应对应。它比逐像素一致更接近本文的 [oracle](../glossary.md#oracle)。
- **[精确率与召回率](../glossary.md#metrics)**：前者关注报告中有多少真问题，后者关注已标注真问题中找到多少。本文以控件相关的重排问题为对象，不是已修复代码缺陷比例。

## 动机

依据：§1–2，PDF第1–4页。作者以网页重排后仍应保留信息和功能为判定原则。固定截图或DOM规则只能判断当前状态；正常折叠菜单会让控件从当前截图消失，错误实现也可能让某项功能永久消失，两者需要交互才能区分。

原文的 Mailinator 案例（§2.2，图1，第3页）中，宽屏有七个导航选项；窄屏菜单展开后能看到五个，但 FAQ、API 两项仍然缺失。正确流程不是看到汉堡菜单就认定所有功能保留，也不是看到原文字消失就立即报错，而是实际打开菜单核对。

## 贡献

按§1作者条目归纳：

1. 提出面向响应式重排的信息与功能丢失检测方法，连接结构提取、实际交互、语义匹配与目标驱动探索。
2. 与五种已有工具及两种直接模型基线比较，并通过移除探索、只滚动、只展开的消融检查组件作用。
3. 扩展网页领域、后端模型和视口配置，评价方法的适用边界；公开代码和实验数据。

核心记为 **method**。公开数据与源码支持复用；论文没有因此自动成为统一的全GUI测试benchmark或harness。

## 方法与核心技术

整体流程为：**宽窄页面提取 → 记录可操作项效果 → 初次对应匹配 → 生成缺失候选 → 滚动/展开寻找 → 重新匹配 → 报告剩余缺失项**。依据§3，PDF第4–8页。

### 1. 提取实际可见、具有信息或操作意义的控件

文本先从DOM获取并规范化空白；图像候选包括 img、ARIA的img角色与SVG等。信息性图像要求有非空alt替代文本；可操作项包括原生按钮、链接及附有鼠标事件的自定义元素。

可见性判断分三级：Selenium的显示属性检查、位于视口内的坐标检查，以及红色/白色边框的截图复核。最后一级给同一目标分别加不同颜色标记，通过画面是否变化辅助验证是否真正渲染。前两级先过滤明显不可见对象，减少截图开销。

**范围限制**：这不是通用遮挡证明；无alt且不能操作的图像可能直接不在目标范围内，不能把它的缺失算成工具已覆盖的显示问题。

### 2. 实际点击，提取用户可观察的功能

工具用XPath定位可操作项，保存点击前后截图和URL变化。功能在这里主要由可观察的点击结果描述，不是完整业务规格。如果点击仅产生视觉高亮、不揭示新信息或导航，作者将其排除在功能完整性检查之外。

实现会刷新页面，在对象可见后点击并等待结果。论文的操作重心是点击，不应补写成已经系统处理表单输入、拖动、复杂登录或跨页面事务。

### 3. 信息等价与功能等价分别检查

纯信息项先按文字或alt精确匹配。若同一文字出现多次，模型结合带框截图判断上下文是否对应。例如不同房源均显示相同评分，不能因为数字相同就判断相同信息已保留。

对功能项，跨页面导航以移除查询参数后的URL比较；不发生页面跳转时，模型比较宽屏、窄屏各自点击前后的四张截图。既有信息又有功能的对象，两方面都要检查。

**我们的观察**：去掉URL查询参数有助于忽略噪声，也可能合并参数决定的不同功能；四图语义比较仍依赖模型。网页结构对应上，不等于所有业务结果都经过独立断言检查。

### 4. 未匹配项反过来驱动局部探索

滚动不是盲目自由滑动：系统先利用文字或alt定位候选，再调用浏览器滚动到目标。找到后重新提取、比较功能与信息，并从缺失候选中移除已确认保留的项。

展开则将目标标识及清洗后的HTML提供给模型，生成Selenium Python或JavaScript，尝试打开菜单、折叠区。执行错误会回传代码与错误信息，避免重复失败。成功路径也会记录下来，再做同样的等价性检查。

停止条件为候选全部找到、模型判断剩余项不可达，或超过请求上限；实验上限为3。**预算耗尽或模型说不可达，并不是数学上的不可达证明**，多层菜单搜不充分仍可能误报。

### 5. 完整案例与探索的真实作用

回到Mailinator：宽屏FAQ文字是测试参照；初次窄屏没有对应项只是候选；打开汉堡菜单后，对已出现的导航撤销缺失判断，FAQ与API若仍无对应项则报告。它是一种“带目标的寻找反证”，探索用于降低误报，而不仅是走到更多页面。

这也解释了消融中一个容易误读的现象：不探索时把更多项都报缺失，召回反而可能略升，但报告可信度变差。不能以召回单项上升证明探索无用。

### 比较对象与主要结果

已有工具为GenA11y、SALAD、ReDeCheck、WAVE、QualWeb，另有GPT-4.1直接提示及结构化提示。它们的原任务范围不同，作者将输出适配到重排问题；不是七个都原生解决相同任务。

| 设置 | Precision | Recall | 解释 |
|---|---:|---:|---|
| ReFLAIR，24网页 | 80.49% | 95.31% | 主集结果，3次平均 |
| GenA11y，24网页 | 60.00% | 8.45% | 结构和语义检查，动态可见性覆盖不同 |
| GPT-4.1结构化提示，24网页 | 57.82% | 39.91% | 同模型但无完整动态流程 |
| ReFLAIR，SALAD重合子集 | 74.90% | 96.41% | 不能与24页整体行直接等同 |
| SALAD，对应子集 | 27.85% | 67.69% | 未重跑不可得工具，引用项目网站的既有结果 |
| ReFLAIR，36网页扩展 | 84.62% | 93.32% | 2次；非独立于主集的36页新样本 |

出处：表2、第11–13页，§4.4.1、第17页。摘要的20.49%与55.40%对应80.49−60.00、95.31−39.91的**百分点差**，且最强对照分别来自不同方法。不能原样说成统一相对增幅。

论文未在主表给出可直接复算全部P/R的逐页TP/FP/FN明细及明确聚合公式，不自行补充微平均或宏平均口径。也未报告新发现问题的开发者确认/修复总数。

### 消融：主动寻找主要帮助过滤误报

表4（第16页）报告移除全部探索后precision变化−40.08%、recall变化+3.28%；只滚动分别−16.65%/+1.64%；只展开−21.61%/+1.17%。表中使用百分号但不列各变体绝对P/R和变化公式，因此保留原值，不自行换算成绝对得分或百分点。

可以可靠解释的机制是：隐藏在菜单和视口外的正常项，不探索时也会被报成缺失。滚动和展开提供了撤销误报的证据；二者作用互补。该实验没有单独证明每个DOM字段或每种提示均有独立贡献。

### 成本：API费用不高，不代表运行快

主集每次网页分析平均561,590 tokens，输入占绝大多数；中位252,294，最大约268万，平均大于中位是复杂页面拉高。按作者实验时定价，平均$1.18/网页、中位$0.54、最大$5.53，不能作2026-10的现行价格。

实测累计顺序时间平均11,610秒，即3.23小时/网页。控件提取与功能提取合计约占73.19%，其中刷新等待至多20秒、滚动后3秒、点击后10秒，单控件最多33秒等待。页面平均181个相关控件。2.04小时和39.05分钟来自不同层级的并行化**估算**，不是已部署实测加速效果。扩展集平均4.54小时/网页；复杂页面的时延仍是明显代价。

出处：§4.2，表3、第14–16页，§4.4.1、第17页。

## 局限

### 论文明确承认

- §4.1.6、图6–10（第12–14页）：多层展开可能搜不充分；滚动吸附中的短暂文字暴露，以及自动轮播的时间差，会导致错误缺失判断。
- §5（第18–19页）：复杂事件驱动、多步骤工作流不在当前完整模型内；离线副本可能丢图标、改变HTTP安全设置或交互，虽然真值和工具都在同副本评价，仍限制在线外推。
- 人工真值有主观性；主配置偏Firefox与320宽。跨浏览器仅对5页42个问题做Firefox/Chrome人工检查，不是全套工具跨浏览器运行对比；6页一次的后端/视口试验也不能证明任意模型任意设备泛化。

### 我们根据证据提出的观察

1. **参照是宽屏实现，不是独立需求规格。** 它主要查宽窄保持关系，不能发现两版共同错误，也无法自动处理所有业务允许的移动端功能裁剪。
2. **信息不在初屏、暂时不可见与真正不可达必须区分。** 论文已用滚动与展开作部分处理，但3次预算、轮播状态和手势结束状态仍会影响判断；它为后续研究提供具体失败条件，而不是证明主动验证已彻底解决。
3. **不能直接迁移为纯截图手机算法。** 它依赖DOM、XPath、alt和浏览器程序滚动；原生Android中的控件树缺失、嵌套滚动与手势吸附需要另行验证。
4. **预算和判定置信应联合考察。** 搜索成本很大，剩余候选可能既包含真缺陷也包含尚未找到的正常功能。可研究何时补证、何时报告不确定，但这是后续假设，不是已证明的新颖性。

## 和我们课题的关系

### 与 UX testing 的关系

直接研究窄屏适配后信息和功能是否可用。与“截图提出候选—结构核对—主动滑动复核”的关系非常直接：它已经存在候选驱动滚动、展开并重新判定的闭环，适合作为最邻近工作对照。可比较其目标标识依赖、嵌套交互支持、临时状态误报、搜索预算和运行成本；不能仅把从静态到动态写成创新。

### 与 GUI testing 的关系

将局部定向探索与关系型oracle结合：参考布局决定该找什么，运行时交互提供反证，再判断语义和功能是否保留。它不是无目标全应用覆盖器，也不是完整页面任务导航benchmark。它提供了“探索服务于判错”的具体范式，而非所有模块都只追求到更多页面。
