# MLLM as a UI Judge：怎样把模型评分与人类界面感受逐项对照

> 原创中文笔记；2026-11-06重写。全文依据arXiv:2510.08783v1（2025-10-09）§3–5与附录B；证据深度full / extracted，未复现。正式发表情况未另核实，记为该预印本版本。

## 一页读懂

| 问题 | 本文的回答 |

| 研究什么 | 静态界面看起来是否易用、清楚、可信、好看；模型能否模拟人的评分和偏好。 |
| 输入输出 | 单图＋九维评价问题，输出1–7分；或双图＋相同问题，逐维选择偏好。 |

| 模型处理 | GPT-4o、Claude 3.5 Sonnet、Llama-3.2-11B-Vision；单图每界面每维10次取中位数，没有训练新模型。 |

## 一段话介绍

作者关心设计早期没资源对每个方案做用户研究时，模型能否提供方向性反馈。它把“像不像人”拆成三个可计算问题：给分是否接近、对界面的排序是否接近、面对两图是否选中人更偏好的一个。人类先看单图按九因素评分；模型做同类任务。成对人类真值由先前平均分推导，而不是再组织一轮双图人类实验。方法的关键是建立评价协议和分析不同指标，贡献为benchmark与实证研究。

## 术语与任务定义

- **Likert量表**：本篇1到7表示对陈述从强烈不同意到强烈同意；评分针对“看起来易用”等印象。
- **均值与中位数**：人类多份评分取均值，模型重复10次取中位数，减少单次随机输出影响。
- **绝对分数误差**：比较模型给6分和人类平均5分差多少。
- **排序/偏好**：比较A与B谁高；模型整体偏低仍可能排对顺序。
- **±1准确率**：相对四舍五入的人类分数，模型误差不超过1的比例。
- **相关系数**：Pearson看数值同步变化，Spearman看排名，Kendall看成对次序一致程度。

## 动机

早期设计方案多而用户研究资源有限，作者希望用模型辅助筛选。点击率、转化率等行为指标不能直接说明布局清晰、可信等主观反应；另一方面流畅评论也可能偏离人的实际感受。因此需要同图、同维度下的人类与模型对照，而非让模型自行解释自己是否正确（§1–2）。

## 贡献

1. 建立九维静态UI主观评分的人类/模型对照数据。
2. 将绝对分数、排序和直接双图偏好分别建任务。
3. 分析偏好差距大小对模型可靠性的影响，给早期设计辅助提出适用范围。微调与RLHF在本文是未来应用，不是已执行方法。

## 方法与评价流程

### 1. 怎样选界面

从Really Good Emails专业界面来源选30图，24个专业制作、6个自制；覆盖浏览发现、确认反馈、沟通参与三类。作者控制截图高度，兼顾移动与桌面外观，并降低部分图的制作质量来增加差异。后续预处理中剔除非专业制作界面；因此“初始30图”与最终有效样本需区分。正文未统一列出过滤后每项实验的完整界面清单（§3.1、§3.4）。

### 2. 九个因素，问题究竟问什么

| 组 | 因素 | 给人的陈述 |
|---|---|---|
| 认知 | Ease of Use | 看起来容易使用 |
| 认知 | Clarity | 布局清楚、不杂乱 |
| 认知 | Visual Hierarchy | 有明确视觉层次 |
| 感知 | Memorable | 容易记住 |
| 感知 | Trust | 看起来可信 |
| 感知 | Intuitive | 功能/用途直观 |
| 情绪 | Aesthetic Pleasure | 美观、令人愉悦 |
| 情绪 | Interest | 有趣 |
| 情绪 | Comfort | 令人舒适 |

每项1–7分。这里“易用”是从截图形成的印象，没有实际操作完成率或误触日志（表1、§3.2）。

### 3. 人类数据怎么收集和过滤

AMT参与者准入条件为认可率超过98%、至少500条历史回答。论文报告500参与者、15000份初始回答，每界面目标500份。每次先对九维评分，可缩放图像查看，再写评分理由；预计45秒至1分钟，每500份费用75美元，总2250美元（未含税费）。

保留worker ID、image ID、界面类别和九维分数；剔除少于45秒、未完成、同用户重复评分和非专业图的数据，得到9296份。对每个有效界面i、因素f求人类均值h(i,f)，作为后续参照（§3.3–4）。每份回答含九维，所以9296不是9296张不同图。

### 4. 单图模型怎样调用

同一UI和评价因素提供给三种固定模型，按附录图7的量表指令给分。每个UI/因素重复10次，取中位数m(i,f)。模型只收到静态图与评价问题，没有树、执行轨迹或新训练权重（§4.1）。

### 5. 分数怎样比较

设共有N个UI—因素观测。原文指标可整理为：

```text
MSE = Σ(m-h)²/N
MAE = Σ|m-h|/N
Accuracy = count[m = round(h)]/N
Accuracy±1 = count[|m-round(h)| ≤ 1]/N
```

前两项用未取整均值，后两项以人类均值取整后匹配。MSE会更重罚大偏差。整体都打6分，可能得到较小MAE，却分不出不同界面的差别，所以还要算排名相关性（§4.1.2）。

### 6. 排名怎样比较

逐因素把人类均分和模型中位分排列，计算Pearson、Spearman、Kendall。原文将Kendall的0.4/0.6/0.8解释为约70%/80%/90%成对次序一致；该直观换算适于无平局的简化情形，实际还要看所用tau版本及平局处理。

原文Interesting维度数值误差大但排序相关高；Comfort误差小却排序相关低。模型可能系统性低估有趣程度而保留次序，也可能所有舒适度给近似高分从而缺乏区分力（§4.1.3）。

### 7. 双图偏好真值怎样生成

对界面A/B与因素f，用既有人类均分比较：

```text
h(A,f) > h(B,f) → 人类参照偏好A
```

模型直接接收两图及附录图8指令，逐因素选偏好。选边相同记正确，逐因素算比例，再对因素平均。作者没有重新请人做全量双图选择。均分完全相同的图对如何处理、双图每对是否同样重复10次，正文没有像单图协议那样完整交代（§4.2.1）。

### 8. 怎样分析“容易的比较”和“难的比较”

计算每图对每因素的人类分差δ=|h(A,f)-h(B,f)|，按δ分桶，分别算模型选边正确率。小分差桶中接近50%；大分差桶GPT-4o/Claude接近90%/93%，Llama约60%。这解释了为何只看宽松打分指标会高估精细区分能力（§4.2.2、图3）。

### 9. 数值贯穿例

自编例子：A/B的清晰度人类均分为6.2/5.1，模型给6/5，则精确取整匹配与排序都正确。若两图人类均分为6.2/6.1，模型仍给6/6，量表误差很小，但已失去区分；直接双图选择可能接近随机。此例说明三种任务的不同，不是论文样本。

## 实验结果

## 原文版本疑点

本文数值以结果表为锚点：引言称三模型±1均超过75%，表3为72%–77%；讨论§5.1写Claude48%、GPT40%及不同MAE/MSE区间，与表3整体行不同；§4.2正文写Llama约51.79%，表4为52.96%。原文未解释这些差异。最终有效界面清单和完整平局协议也需查原始补充数据；不自行补成精确全量实验。

## 局限、用途与研究联系

静态专业设计截图、评分集中高分、西方设计语境及有限模型是作者主要限制。本文无App探索、UI树或交互验证。对显示缺陷评价可借：明确每个评价问题、保留多人评分分布、区分绝对误差与成对判断、按样本难度分层。若用于产品缺陷，另建对象损失与恢复标签，避免把“感觉好看”混成具体异常。
