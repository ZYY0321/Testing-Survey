# MLLM as a UI Judge：模型能否预测人对界面的主观感受

> 阅读定位：外围评价方法参考，不是显示缺陷检测基线。核查日期：2026-11-06。所读版本：arXiv:2510.08783v1，2025-10-09；本轮未核实后续正式发表。核对全文任务设计、数据过滤及评价结构，未复现结果。本文为原创中文 note。

## 研究问题与输入输出

论文问多模态模型能否近似人对界面的印象。输入为静态 UI 图像和评价问题，输出为 1—7 分的主观评分，或两个界面之间的偏好。维度包括易用感、清晰度、视觉层次、可信感、直观感和情绪感受等。它不是在判断应用运行是否符合规格。

研究先选取 30 个界面并收集众包评价，再用 GPT-4o、Claude 3.5 Sonnet 和 Llama-3.2-11B-Vision-Instruct 等固定版本模型对同样材料打分。原始约 15000 份评价经过时长、重复、不完整及非专业制作界面等过滤，保留 9296 份。因此“30 个初始界面”不能未经核对就当作所有最终实验共同使用的有效样本量。

## 为什么同时做打分和成对偏好

**自编例子：** 对同一收据界面，人给清晰度 5 分，模型给 6 分。若允许误差一分，这算接近；但当比较两个几乎一样的收据布局时，模型可能仍无法选出人更喜欢的那个。绝对分数接近、排序接近、成对选择正确是三个问题，不能互相替代。

作者分别看评分误差与相关性，并研究人类偏好差距大小对成对选择的影响。论文总体结论是：模型能近似部分人类偏好，但更适合辅助早期筛选，不适合代替人类研究。该结论适用其界面与主观评价协议，不能推出运行时 bug 识别已达到相同能力。

## 怎样读它的结果

若样本大多设计质量较好，模型和人都给较高分，一个宽松容差指标可能看起来不错，却未必能区分细微差别。相关系数也不能说明模型在某个具体页面上的解释是否真实。实际借鉴时，应同时看分数分布、细微差异样本和失误类型，而不是只摘取一个“准确率”。这段是对评价含义的分析，不是声称所有问题都由原文实验解决。

模型版本、提示和数据范围都应保留：2025 年对固定模型的结果，不能自动作为 2026 年所有模型的能力结论。论文许可显示为 CC BY-NC-SA 4.0；本 note 没有复制原图或提供其全文译本。基准数据原文指向补充材料，本轮没有确认独立可直接下载的数据包。

## 与截断判定的距离

**自编反例：** 两个购物界面 A 和 B，A 更漂亮但底部价格被裁掉，B 外观普通但信息完整。偏好模型可能选 A；缺陷 oracle 则必须单独识别价格缺失。这说明主观偏好不能替代有具体错误定义的判断器。

对于截断，关键问题是内容是否缺失、是否属于预期省略、是否可通过有效操作取回，以及缺失是否影响任务。论文不读取 UX 树，也不通过滑动或展开操作验证这些条件。它最有用的启发是评价应拆成多个明确问题：整体印象、局部可读性、缺陷存在性和操作后的恢复性分别建标签。

如果需要人类真值，还应保留标注者分歧。很多人觉得“看起来正常”不等于应用规格证明它正确；同样，模型解释流畅也不能作为自身判定正确的证据。这些是面向缺陷评价的建议，不是该论文提出的新截断方法。
