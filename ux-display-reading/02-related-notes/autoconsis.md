# AutoConsis：跨页面内容一致性检测，与视觉截断有什么不同

**书目**：AutoConsis: Automatic GUI-driven Data Inconsistency Detection of Mobile Apps，ICSE 2024 Software Engineering in Practice（SEIP，工业实践赛道）。本次依据作者团队官方技术介绍整理，**不是全文级论文复核**；实验细节和完整误差分析仍需论文原文。状态 `official-technical-report / extracted`。

## 一次测试在做什么

同一商品可能出现在营销列表、详情页和提单页。页面分别显示不同价格时，检测器要先判断比较的是不是同一商品、价格类型是不是相同、优惠条件是否一致，再判断差异是否违反业务规则。单看任意一张截图通常都可能正常。

官方介绍的处理流程为目标区域识别、信息提取、一致性检查。区域检索结合图像示例和文字描述；OCR 与 UI 元素分析得到局部内容；语言模型解释价格及优惠；最后按数值规则或语义条件判一致性。它没有把所有判断都交给模型自由回答。

## 为什么不直接把整页文字发给模型

页面上可能同时有原价、到手价、券后价、会员价和其他商品的推荐价格。直接把 OCR 文本拼接后，空间归属关系容易丢失。先定位商品卡片，再抽取字段，可以减少无关内容，也使“这个价格属于哪个商品”更明确。

注意：这里的区域裁切是检测系统对输入截图进行的预处理，与被测应用的文字被错误裁切不是同一种“截断”。术语相同不能推断研究问题相同。

## 自编例子：差异不总是 bug

列表写“100 元，满 100 减 20”，详情写“优惠后 80 元”，提单写“实付 80 元”。直接比较字符会错误地报告 100 与 80 不一致。检测器需要先解析价格含义及适用条件，再比较有效价格。如果用户在两个页面间切换了会员资格、城市或商品规格，也需将条件变化纳入证据。

反过来，若所有页都显示 80 元，但后端应为 70 元，仅做跨页相等检查可能全部通过。这说明一致性 oracle 能发现相互矛盾，却不等于验证每个值对独立需求规格都正确。这是关系检查的一般边界，不是论文宣称覆盖的任务。

## 对截断研究可以借什么

可借鉴的机制是先锁定同一对象、再组织局部证据，并明确比较成立的前提。研究一个长文本在不同窗口尺寸下是否丢失时，同样要确认文本内容、业务状态、页面对象一致，才能把差异归因于布局。

但 AutoConsis 的业务预期来自事先规定的一致性规则；文字能否通过滚动或展开访问，需要另外的行为证据。它也没有提供 Android 或 HarmonyOS 裁切节点的统一树字段判定规则。将其列为旁读，是为了理解“正确性依据与对象对应”，不应当作最直接的截断检测基线。
