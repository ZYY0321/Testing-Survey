## 2. 它实际研究什么，为什么与 UX 有关

UI-Lens 提供显示质量评测数据与规则，研究通用多模态模型是否能识别界面的细微显示异常。它不是能自己探索手机的 GUI Agent。单次输入已经是一张选好的截图，再加“本次检查文字溢出”等类别专用提示；模型返回问题数量、说明和粗位置。评分主要把数量转为“本类别有/无问题”，与该类别人工标签比较。框标注存在，不代表当前评测计算了框定位精度。

五种单屏任务分别是：文字越出可见容器边界；内容在容器内硬裁切；组件错误重叠；应有内容未显示；异常使用省略号。另有跨屏文字不一致任务，本次没有运行。UX 是用户体验，其中显示可读性与可操作性只是部分；这个任务不能评价整套业务是否合理、流程是否易用。原文来源为 [CVF 正式论文](https://openaccess.thecvf.com/content/CVPR2026/papers/Xiang_UI-Lens_Assessing_General_MLLMs_Potential_to_Automate_UI_Display_Quality_CVPR_2026_paper.pdf)；本次网页检索定位到该官方来源，但直接读取返回 403，详细协议和表格数字依据仓库中此前阅读全文形成的 note 及本地原材料，不将第三方解读作为证据。

提示明确排除正常占位头像、加载中状态、视频内文字、部分浮层、正常可滚动边缘露出和长文省略。这一点决定了它不是“检测所有矩形相交或半字”。例如列表只在屏幕右缘露出下一项，可能是可横滑的提示；只有一张图时，是否真的可滑动并未被实验验证。

## 4. 过程、技术问题与处理

正式实验目录经历 FORMAL_01/02/03，并非三轮科学重复。前段已有响应在续跑时复用，不重新付费请求；最终实验本身始终只有 200 图、两轮。20 并发曾出现 ConnectionError，后续降低为 4；模型、图片、类别、评分定义未因结果好坏修改。最终 manifest 的 371 个新调用和 29 个复用回答描述该运行阶段；另有 9 次技术重试，不应把它们机械当成 400 次总尝试。

最初要求整个回答必须是一个 JSON 对象，但模型常在前后加说明或代码围栏，严格格式有效率均值为 0%。后续只抽取唯一、完整且符合预先 schema 的类别报告，不改布尔值、不修计数、不用标签选答案；歧义、多报告、截断和不合法字段仍失败。因此最终检测得分不能称为“严格格式遵循成绩”或“作者官方解析器成绩”。

首次有 8 项无可用报告，追加 9 次同请求技术重试后解决，原失败和各次回答均保留。正常误报、漏报不允许据标签重试。首次两轮有效率 97.5%/98.5%，含技术失败完整分母准确率 67.5%/73%；技术重试后有效率均 100%，准确率成为 70%/74%。这说明“补齐系统输出”改变成绩口径，必须同时保留首次和补齐后结果。

最终 400 个被选中的唯一 response ID、prompt、实际输入图、原返回、解析和预测已逐项离线对应核验；这证明记录可追溯，不能证明每个答案正确。固定 20 任务依 `SHA256(20261101|task_id)` 规则选择，AI 实际看 20 张图和 40 份回答；选集含标签，因此不是盲审，也不是论文独立人类一致性实验。

## 5. 数值结果与论文对照

Accuracy 是全部任务中分类正确的比例；Precision 是报异常的任务中有标签异常的比例；Recall 是标签异常任务中被报出的比例；F1 为 Precision 与 Recall 的调和平均。它们的单位是“截图—指定类别任务”，不是独立程序 bug、框或导航任务。

| 第 1 轮 | 45 / 95 / 13 / 47 | 70.00% | 77.59% | 48.91% | 60.00% |
| 第 2 轮 | 52 / 96 / 12 / 40 | 74.00% | 81.25% | 56.52% | 66.67% |
| 两轮指标均值 | 同图重复，不能当 400 独立图 | 72.00% | 79.42% | 52.72% | 63.33% |

论文数字见学习 note“单屏分类的主要结果”，对应原表 2；它们只提供量级背景，不能作本次优于原方法的证据。本次换了模型、提示语言、数据版与子集，各类别正负比也不同。例如本次重叠正例 24/39，而溢出正例仅 16/41；两类 accuracy 接近时，召回和报错倾向可以完全不同。溢出两轮 precision 都为 100%，但只找出 2/16、5/16 正例，不能据高 precision 宣称高检测能力。200 图全部判正常即可得到 108/200=54% accuracy，这也说明 72% accuracy 与“找到 72% 的真实问题”不是同一意思。

两轮同图预测一致 178/200=89%；其中 133 图两次均正确，37 图两次均漏报，8 图两次均误报，22 图预测变化。持续漏报中，溢出 11、缺失 12、重叠 5、裁剪 5、省略 4。重复两遍没有解决大量稳定错误，不能把稳定性等同可靠性，也不能默认多次投票就有 95%准确率。两轮不足以估计充分的模型随机性分布。

最终选中回答 token 为输入 1,195,834、输出 331,667、合计 1,527,501。覆盖 FORMAL_01/02/03 与技术重试、按真实 response ID 去重的账本是 409 份保存响应、已知 usage 1,587,574；记录 465 次 request start，其中 56 次在原尝试未保存响应。缺返回的请求是否收费未知，不能将最终选中 400 答的 usage 当总费用，更不能按无返回数补造零费用。

## 7. 对 UX testing 探索与覆盖的明确判断

**本项目没有应用探索率、Activity 覆盖率或 UX 状态触达率；不能补成 0%，也不能写成 200 页覆盖 100%。** Activity 是 Android 窗口/功能载体，一项 Activity 可以包含多个页面、弹窗、滚动位置；静态图没有访问路径、目标应用完整页面分母或实验动作。能报告的是指定检测任务的输入覆盖：五种单屏类别均有样本、200 个固定任务均产生最终有效输出。它不包含键盘、字体、窗口、滚动、开合、内容加载时序等条件组合的覆盖证明。

对探索器的启发是：发现更多状态只有在采到有诊断价值的条件时才有用。ui-070/181 需要保持同一候选目标的时间变化，ui-122 需要横向容器补证，ui-066 需要同屏多类检查。将这些样本用于定义探索目标是合理的；声称本次已经实际执行了那些验证动作则不成立。

若后续评估“UX 探索覆盖率”，先建立独立目标表，每项定义页面、控件、条件（例如键盘打开/长文本/加载完成）和可检查预期，统计实际触达的目标条件数 / 预定义可达目标条件数。探索预算、检测器和初态固定，分别报告“到了哪里”“触发了什么”“判对了什么”，不能以最终报告数量代替覆盖。

## 9. A/B 两条方向怎样使用这些结果

**A：生成有测试价值、可重放的探索轨迹与用例。** UI-Lens 适合提供目标风险类型与静态候选，用来回答“下一步值得验证哪里”，不能独立充当探索基线。可以把“页面+疑似组件+验证条件+预期+动作+后态证据”作为用例，而非只保存一张异常图。灰块例要求等待/刷新对照，裁剪例要求正确容器中的受控滚动与恢复，单类别负例要求进一步检查其他类别。此处是下一步设计，不是本次已验证的效果。

**B：提高已有 UX 截断/遮挡判断的可靠性。** 这批结果可作冻结的静态多模态模型对照，尤其需要保留持续漏报、正常边缘露出与占位图。我们的系统若增加结构信息、时序或交互，应在同一图/候选、同一标签口径上分别比较“只看图”“图+结构”“图+动作证据”，并将无法判断保留为未知。还应报告 coverage，即能够作出有证据判断的候选比例；只对少数容易案例回答而保持很高 precision，不等于达到总体检测要求。

已有证据支持写进论文的动机是：在该固定子集与 Qwen 配置下，平均召回仅 52.72%，重复两次仍有 37 个持续漏报，且有图像级判对而报告对象依据不足的实例。这说明视觉分类分数不能代替动态可用性、对象定位和可信判错。不能写成“通用模型全部不行”“我们的方法已优于原论文”“动态验证一定能修好这些错误”。

可进一步检验的贡献假设是：针对证据缺口选择少量补证动作，降低错误确信，并在固定时间预算下提高对目标条件的有效覆盖。需用同场景正常/异常对照及独立标签检验，避免沿用模型自己生成的解释作为真值。UI-Lens 自带的正常例外和图像合成经验可用于构造对照；若要评价真实导航故障或恢复，仍需可执行应用，不能只编辑截图就宣称验证了真实操作失败。

## 本次新增实图复查：五类错误怎样用于分析其他探索结果

本次主Agent在报告初稿后，按`case-index`顺序在“五类×正负标签”每一层取首项，先固定10图再逐张打开原存档图片查看。10张均实际查看像素，并对照作者原框及两轮回答。这里是有意平衡类别的解释样本，不是重新抽出的无偏准确率样本；不改变200图原标签或400回答成绩。另一Agent此前实看4张示例属于本次其他审阅，不能把重叠图简单相加为独立样本。

|图ID|本次实际看到什么，以及它解释了什么|
|---|---|
|ui-001|设置分组标题订阅与发票/账号中心位于容器边缘，另底部清理缓存/当前版本与图标挤在一起；作者框对应前两标题。单看模型把它们理解为正常标题层级，解释漏报源于设计意图歧义，而非没访问页面。|
|ui-002|个人页内容和头像可见，横向标签最右只露部分字、底部网格受导航边界截取；作者对undisplayed_content标负，不能把任意边缘裁切当该类阳性。|
|ui-003|卡券列表下方第四张卡部分落到屏外，作者cropped_content负；正常列表视口裁切与异常容器裁切需要区分，不能把列表没全露判bug。|
|ui-004|视频主页作者头像圆圈内部为空，作者框定位该圆圈；支持局部内容空缺现象，单静态图不证明网络加载后仍缺失或可重复。|
|ui-006|积分页横向筛选标签边界紧邻，右端搜索覆盖/淡出区域；作者container_overlap框定位筛选项，需把目标框和原标签保留，不能只凭全图看似整齐改标负。|
|ui-008|设置找回账号右侧找回...和个性...出现省略，且左右仍有空间；作者框指这两项。和正常长备注省略不同，空间/角色条件是关键。|
|ui-019|朋友申请长备注多行后用省略号并有回复入口，作者abnormal_text_ellipsis负；说明有省略号不等于异常。截图有其他头像空白也不自动改变此类标签。|
|ui-024|横屏视频弹幕在屏幕边缘截出，作者text_overflow负；弹幕流的部分出屏不等于静态控件文本溢出。|
|ui-028|电影列表第二排片名只显示上部笔画，下方下一排海报仍可见，中间有白色带状空隙；作者框定位第二排三片名，区别于只在屏幕最末端被视口遮住。|
|ui-062|会员页横向套餐与卡片在左右露边，上方轮播背景与标题叠置；作者container_overlap负，层叠视觉设计与错误容器重叠不同。|

这个对照对B的直接价值是把“可见现象”与“异常标准”分开。ui-028的片名在列表内部被横向白带截掉、下一排仍显示，与ui-003在整个屏幕下边界只露半张卡券不同；ui-008短设置项被省略，与ui-019长备注的省略也不同。这些差别能形成我们的候选复核规则，但没有动作序列时，不应补造“滑一下仍不可见”的结论。对于ui-004的头像空圈，缺失标签可以用于本数据集评价；换到真实探索轨迹时，还应检查加载状态，不能假定一帧空圈就是持久缺陷。

对A的价值是提示“到某个页面”不够：要让列表滚到相同内容密度、让长字段进入特定容器、让横向菜单处于特定位置，才形成可比较的显示条件。其他探索工具是否到达这些条件，需要看它们自己的截图与动作，不能用UI-Lens的截图替代它们的探索产物。该数据集无探索轨迹，因此也不能回答它自身“探索到了多少页面”。
