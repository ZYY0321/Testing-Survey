## 想法怎么变的

每一幕三件事：当时想回答什么、发现了什么、因此改成了什么。

**第一幕 · 10-22 至 10-29 · 开合问题能不能自动收**
- 想回答：写一个自动探索脚本，在鸿蒙折叠屏真机上自动走页面、做开合测试、收问题。
- 发现：过夜跑了 28 个 App，GPT-5.6 打标 849 组、判 fail 266 组（还没人工复核）。覆盖上不去：按布局模板认页面和真实功能对不上（唯品会 35 个模板，按 spec 只走到 46 页里的 10 页），卡住、振荡、登录墙、防截图。
- 改成：不只做开合，先想清楚研究价值在哪、和别人比我们有什么。

**第二幕 · 10-29 · 列出可能的方向**
- 想回答：从诊断结果出发，能做哪些研究（探索、GUI 状态图、轨迹质量、结构树可信度、验证）。
- 发现：她指出几处证据有缺陷（"大模型挑控件不如随机"是因为大模型只在卡住时才调用），写出来的摘要把我们自己实验没做好包装成了动机。
- 改成：先找"我们到底在哪有优势"，不再拿有缺陷的实验当动机。

**第三幕 · 10-30 · 每个方向拆范文、列假设，先复现别人**
- 想回答：每个方向的范文从动机到实验怎么写；我们的动机、贡献分别是哪些待验证的假设。
- 发现：方向二（状态图）已经很拥挤；和结构树有关的已有工作（2607.04334）只做了诊断。她更正了 SE1 的假设：难的是分清真截断和看似能滑的假截断，只看图、加布局树都不行。她判断方向一不突出（截断、开合没有预兆，找到它们约等于覆盖率更高），开合可能两张图就能看出来。
- 改成：四个方向的范文拆解与假设表（[方向分析.md](方向分析.md)）；第零步先复现 8 个开源工具；SE1 改测真假截断；方向一、开合降级；布局树可靠性（AX-1）写成详细做法。

**第四幕 · 10-31 至 11-02 · 复现 8 个工具，加上我们自己两批数据**
- 想回答：别人的工具实际探索到什么、能不能发现 UX 问题；静态判断到底差在哪。
- 发现：
  - 探索和用例生成工具都没有 UX 判定器，路过白屏、破图也不报；动作经常没生效（HapTest 滚动参数、LLMDroid 浮层）。
  - 只看截图的模型 recall 53%（UI-Lens，Qwen3.8-Max）。
  - 我们端到端截断 50 页：不滑动时最好 86%，召回 9/10 但 15 页里误报 6 页；滑动核对后 96%、9/9 没有误报。
  - 我们收轨迹时，不收的 99 条里有 30 条是在加载、白屏上操作。
- 改成：汇报主线定为"可靠的 UX 检测要先确认看到的是真的、做的动作真生效了，再下结论"（[汇报_1103.md](汇报_1103.md)）。

## 目录规范（新文件只能放进这些位置）

```
方向与实验/
  README.md            本页：想法怎么变的 + 实验总表
  原话与决定.md         她的原话和已定决定（每次相关对话当轮追加）
  方向分析.md           四个方向的范文拆解和假设表（假设验证完在对应行补结论）
  待跑的实验.md         每个实验的做法、人力、放弃条件
  汇报_<日期>.md        每次汇报的思路和会上定的事
  材料/                 核实表、模型原文等原始材料
../reproduction/        复现报告（学弟维护，每个工具一篇，catalog.md 是总表）
```

- 每个实验做完：在 `待跑的实验.md` 对应小节末尾写结果（日期、谁做的、关键数字、数据在哪、有没有触发放弃条件），再回来改总表那一行，最后在 `方向分析.md` 对应假设后写"成立 / 不成立"。
- 想法有大变化：在上面"想法怎么变的"加一幕，写清想回答什么、发现了什么、改成了什么。
- 公司 CUA 的数据和结论不放进这个仓库。
